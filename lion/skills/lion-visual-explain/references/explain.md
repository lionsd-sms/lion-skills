# 큰 그림과 짧은 글로 설명하기

## 주제

- 요청에 있는 주제를 쓴다. 호스트가 `Topic:` 또는 인수를 주면 그 값을 쓰되, 비어 있거나 `$ARGUMENTS` 그대로이면 사용자 요청에서 찾는다.
- 앞의 `/eli5` 또는 `eli5`는 호출어다. 주제에 넣지 않는다.
- 주제가 없을 때만 짧은 질문 하나로 주제를 확인한다. 이미 준 주제와 조건은 다시 묻지 않는다.

## 설명과 화면

- 그림이 설명을 이끌게 한다. 문장은 짧은 이름표와 캡션으로 두고, 요소의 관계·변화·순서가 그림에 보이게 한다.
- 비유를 쓰지 않고 실제 부품과 동작을 큰 그림으로 한 부품씩 보인다(예: 주소창 → DNS 서버 → IP 주소가 돌아옴). 짧게 만들려고 원인과 결과를 뒤집거나 필수 조건을 지우지 않는다.
- CSS·SVG·필요한 스크립트를 모두 HTML 안에 넣는다. 외부 폰트·CDN·이미지·스크립트에 기대지 않는다.
- 정확한 수치·글자가 들어가는 그림은 데이터와 SVG로 만든다. 사진·일러스트가 설명의 일부이면 이미지 생성이나 제공된 시각화 도구를 쓰고, 결과를 HTML 안에 내장한다.
- 상호작용은 개념 이해에 도움이 될 때만 넣고 기본 설명은 조작 없이도 읽히게 한다.

## 설명 순서

- 이름과 정의를 먼저 준다. 대상이 무엇인지 일반적인 말로 한두 문장, 통용되는 이름이 있으면 함께 쓴다. 그 뒤에 지금 사례에 이어 붙이고 작동 방식, 이유, 예외 순서로 쌓는다.
- 가장 작은 완결 답을 첫 화면에 둔다. 한두 문장으로 전체가 서면 거기서 멈추고, 더 깊은 층은 그 아래에 접어 두거나 요청이 오면 더한다.
- 부품이 셋 이상이면 그림을 연속으로 둔다. A에서 B까지 그리고, 같은 그림에 C를 더해 다시 그리고, 돌아오는 선이나 다음 조각을 더해 다시 그려서 독자가 구조가 조립되는 것을 본다. 전체를 한 장에 보인 그림은 마지막에 참조용으로 둘 수 있다. 부품 하나로 서는 설명은 그림 하나로 끝낸다.
- 흐름은 사람이 실제로 하는 동작을 따라간다(긴 대화를 열고 위로 스크롤하면 무슨 일이 일어나는가). 함수·상수 목록은 설명 자리에 놓지 않는다.
- 한 개념에는 이름 하나를 정해 끝까지 쓴다.

## 확인

- 그림·캡션·화살표를 다시 읽어 핵심 관계와 단계가 맞고 서로 모순되지 않는지 본다.
- 파일 안의 `src`·`href`·`url()`·`@import`를 찾아 인터넷이 있어야 열리는 참조가 없는지 확인한다.
- 저장한 HTML을 실제 브라우저에서 열어 큰 화면과 작은 화면(폭 375px 안팎)에서 본다.
  - 핵심 그림과 이름표가 함께 보이는가. 잘림·겹침·넘침, SVG 이름표끼리의 겹침, 작은 화면의 글자 크기.
  - 읽기 순서와 제목 구조, 그림의 이름·대체 설명, 색 외에 형태·글자로 구분되는지, 글자 대비.
  - 글꼴 대체 뒤에도 줄바꿈과 배치가 유지되는가. 연속 그림은 각 그림이 앞 그림에 부품 하나를 더한 모양인가.
  - 조작이 있으면 초기 상태, 조작 뒤 상태, 키보드 조작, 동작을 줄이는 설정에서의 화면.
- 브라우저를 실행하지 못하면 구조·외부 자원 검사까지 하고 화면 확인을 못 했다고 한 번 밝힌다. 따로 그린 그림은 렌더링 증거가 아니다.

## 전달

1. 호스트가 HTML artifact를 지원하면 그 artifact로 전달한다.
2. 파일로 전달하는 호스트에서는 사용자가 지정한 출력 위치에 `.html`을 저장한다. 지정하지 않았으면 현재 작업 폴더와 프로젝트의 출력 관례를 따른다. 스킬 자체 폴더에는 결과를 저장하지 않는다. 실제 파일의 전체 절대 경로를 클릭 가능한 링크로 주고, 호스트의 파일 미리보기가 있으면 함께 연다.
