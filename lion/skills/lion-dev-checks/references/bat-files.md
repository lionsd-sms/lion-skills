# 실행 파일(.bat)

실행 파일은 이미 있는 권위 있는 명령을 짧고 되풀이할 수 있게 부르는 얇은 감싸기다: 인자·환경 확인 → 표준 명령 호출 → 종료 코드 그대로 전달(실패하면 0이 아닌 종료 코드) → 할 일이 보이는 결과 표시.

## 본문

- 새로 쓰거나 고치는 .bat 본문은 ASCII로 쓴다. 한글 출력은 호출하는 PowerShell 스크립트에 두고 .bat은 인자·종료 코드를 전달한다. 파일 이름은 한글을 허용한다.
- 모든 실행 경로는 따옴표로 묶는다.

## 자리

- 프로젝트 규칙 문서의 폴더 틀 절(`틀:` 줄)이 실행 파일의 이름과 자리를 정했으면 그대로 따른다.
- 틀이 정한 실행 파일은 요청·완성 윤곽·사용자 결정이 그 역할을 요구할 때 만들거나 배포한다. 실행·배포·판 보관은 별도 요청이 있을 때 시작한다.
- 틀이 없으면 프로젝트의 기존 관례와 프레임워크 기본 자리를 따른다. 관례가 없고 사람이 직접 되풀이해 쓰는 공용 실행 파일이 필요하면 `scripts/`에 두고 이름은 사용자에게 묻는다.
- 기존 deploy.bat이나 자동 실행 명령이 권위면 그 로직을 복제하지 않고 그 명령을 부르게 한다.
- 사용자가 루트 바로가기를 원하면 루트의 .bat은 표준 실행 파일을 부르는 짧은 감싸기로 만든다.

```bat
@echo off
call "%~dp0scripts\dev.bat" %*
exit /b %errorlevel%
```

## 이름 정하기

1. 이번 사용자가 밝힌 이름 → 대상 앱·패키지의 확인된 표시·제품 이름 → 그 명세 파일의 프로젝트·패키지 이름 → 실제 프로젝트 루트 이름 순으로 정한다. 여러 앱이 든 저장소는 바꾸는 앱의 이름을 쓴다. 이름을 확인할 수 없으면 자리표시자 상태의 실행 파일을 내지 않는다.
2. 한글·공백은 그대로 두고 이름은 유니코드 NFC로 맞춘다. 파일 경로·셸에서 위험한 글자와 제어 문자는 안전한 글자로 바꾸고 바뀐 이름을 보고한다. 이름이 부딪치면 덮어쓰지 않고 실제 대상과 기존 주인을 대조한다.
3. 이름을 바꾸면 호출부·README·문서 링크를 같은 변경에서 맞춘다.
4. 컴파일러의 `build/`·`dist/`·`.next/`, 플랫폼 패키지 ID·이미지 태그·서명 대상 파일 이름은 그대로 둔다.
