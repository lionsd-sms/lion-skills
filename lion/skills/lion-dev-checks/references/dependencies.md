# 새 패키지 확인

## 고르기 전

- 같은 책임을 이미 맡는 표준 기능·설치된 의존성이 있는지 먼저 확인한다.
- 새 패키지는 레지스트리에 그 이름이 있는지, 비슷한 이름의 다른 패키지가 아닌지 확인하고, 확인한 출처를 보고의 확인 줄에 적는다.
- 새 의존성·잠금 파일 차이·설치 스크립트 정책 변경은 소유자·유지 상태·배포 시기·출처·전이 의존성으로 함께 본다. 서명 검증을 지원하는 패키지 관리자는 검증한다.
- 판에 민감한 API·동작·설정 문법은 실제 설치 판의 공식 문서로 정한다. 최신이라는 까닭으로 프로젝트의 고정 판을 올리지 않는다.

## 설치

- 잠금 파일을 소유한 작업 루트와 패키지 관리자를 먼저 찾는다. 선언된 관리자, 잠금 파일, CI 설정이 서로 어긋나거나 잠금 파일이 둘이면 멈추고 보고한다. 관리자 판은 고정한다.
- 새 의존성을 처음 설치할 때는 설치 스크립트를 끈 채 설치하거나 패키지 관리자의 허용 목록 방식을 쓴다. 스크립트가 꼭 필요한 패키지만 그 내용과 판을 읽은 뒤 허용한다.
- 그 허용 목록은 프로젝트 설정 파일(예: `.npmrc`)에 남겨 같은 저장소에서 설치하는 사람에게도 걸리게 한다. 끄고 허용하는 방법은 쓰는 패키지 관리자 판의 공식 문서에서 확인한다.
- 잠금 파일이 프로젝트 계약이면 같은 변경 단위에서 고친다. 판 올림은 패키지 하나나 함께 바뀌어야 하는 작은 묶음씩 하고, 잠금 파일 차이에서 딸려 바뀐 간접 의존성을 확인한다.
- 판을 올리기 전과 뒤에 같은 시험 명령을 돌려 결과를 견준다. 올리기 전부터 있던 실패는 기준선으로 따로 적는다.

## 출시 전 의존성 감사

- 판을 낼 때마다 패키지 관리자의 알려진 취약점 검사를 잠금 파일 기준으로 돌린다. 이 검사는 이미 알려진 권고만 잡으므로 새 의존성은 「고르기 전」 기준으로 따로 본다.
- 높음 이상은 실행·빌드·시험·배포 경로에서 실제로 쓰이는지와 고친 판이 있는지로 가른다.
- 강제 일괄 고침(`npm audit fix --force` 따위)은 쓰지 않는다.
- 고치지 않고 미루는 것은 까닭과 다시 볼 날을 끝 보고 「확인 못 한 것」에 적는다.
