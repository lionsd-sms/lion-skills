# updater 와 서명

## 1. 공식 updater

- 공식 updater 는 업데이트 서명을 끌 수 없다. 공개키는 `plugins.updater.pubkey` 에 파일 경로가 아닌 내용으로 넣고, 비밀키는 빌드 때 환경 변수 `TAURI_SIGNING_PRIVATE_KEY` 로만 준다(`.env` 파일은 안 된다). 비밀키를 잃으면 이미 설치된 앱에 새 업데이트를 낼 수 없다.
- 이 서명은 updater 가 받은 파일을 검증하는 키이고 Windows 코드 서명(Authenticode, 인증서)과 다르다. 3절의 코드 서명 결정과 무관하다.
- `endpoints` 는 운영 빌드에서 TLS 가 강제되고 `dangerousInsecureTransportProtocol` 로만 풀린다.
- Windows 설치 방식은 `passive`(기본)·`basicUi`·`quiet` 이고 `quiet` 는 사용자 설치이거나 앱이 이미 관리자 권한일 때만 된다. 내림 설치는 `version_comparator` 로 따로 허용해야 한다.

## 2. 자체 업데이트를 설계할 때

공식 방식과 다음을 비교해 차이를 설계 문서에 적는다.

1. 무결성 근거의 자리: 공식 방식은 검증 키를 앱 안에 두고 서명 비밀키는 빌드하는 쪽만 가진다. 설치판과 그 해시가 같은 쓰기 권한의 자리(같은 공유 폴더)에 있으면 그 자리에 쓸 수 있는 사람이 둘을 함께 바꿀 수 있다. 공식 문서는 manifest 서버·빌드 서버·설치판 호스팅을 잃으면 보호가 없다고 적는다.
2. 판 비교: 설치판은 내림 설치를 막아 주지 않으므로 앱이 설치판을 띄우기 전에 판을 비교한다. 아래는 NSIS 템플릿 원문을 읽어 얻은 내용이다(확인: tauri-bundler 2.9.4 템플릿).
   - `allowDowngrades` 기본값은 true 다. false 여도 템플릿이 막는 것은 화면 설치의 「제거하지 않고 설치」 단추뿐이고, 「제거 후 설치」 를 고르면 옛 판이 깔린다.
   - 판 비교 값은 쪽 함수 `PageReinstall` 에서만 채워지고 조용한 설치에서는 쪽 함수가 불리지 않으므로 `/S` 의 검사는 막지 못하며, `/P`·`/UPDATE` 도 막지 않는다(`/UPDATE` 는 제거 단계 없이 진행한다).
   - 미확인: 위 두 줄은 실제 설치로 돌려 보지 못했다. 이 동작에 기대는 설계는 실제 설치로 먼저 확인한다.
3. 설치판 명령행(확인: tauri-bundler 2.9.4 템플릿): `/P`(진행 막대만), `/NS`(바로가기 없음), `/UPDATE`, `/R`(`/P`·`/S` 에서 설치 뒤 실행), `/ARGS` 를 받는다. `/UPDATE` 로 띄우면 WebView2 런타임이 없을 때의 설치 단계만 건너뛰고, 설치된 런타임이 `minimumWebview2Version` 보다 낮으면 그대로 올리려 한다.
4. 받은 설치판은 검증한 뒤 다른 프로세스가 바꿀 수 없는 자리의 그 파일을 실행한다.

## 3. 서명 없는 설치판의 경고

- 코드 서명은 고객·계약이 요구할 때만 다룬다. 요구가 없으면 서명 체계를 새로 만들지 않고, 서명을 배포 조건이나 보고 항목으로 두지 않는다.
- 요구가 있으면 방식과 인증서는 고객 요구에 맞춰 정한다. Tauri 의 해당 설정 키는 `bundle.windows` 절에 있다.
- SmartScreen 은 인터넷에서 받은 파일이 잘 알려지고 자주 받는 파일 목록에 없으면 경고한다. 파일·앱·인증서에 평판이 쌓여 있으면 경고하지 않는다. 공식 문서는 내부 위치나 UNC 경로 공유 폴더의 파일은 보호 대상이 아니라고 적는다.
- 잘못 뜬 SmartScreen 경고는 Microsoft 에 파일을 제출해 검토를 요청할 수 있다(제출 화면에서 Microsoft Defender SmartScreen 을 고른다).
- 스마트 앱 컨트롤은 Windows 11 을 새로 설치(초기화 포함)한 PC 에서만 켜질 수 있다. 적용 모드면 Microsoft 앱 인텔리전스가 안전하다고 보지 않은 앱은 신뢰 루트 프로그램 CA 의 인증서로 서명돼 있어야 실행되고, 알 수 없는 서명 없는 코드는 막힌다. 평가 모드는 막지 않고 지켜본다. 상태는 설정 > Windows 보안 > 앱 및 브라우저 컨트롤에서 보인다.
- 현장에서 서명 없는 설치판이나 exe 가 스마트 앱 컨트롤에 막히면 그 PC 가 적용 모드라는 뜻이다. 그 PC 의 보안 설정은 그 현장의 PC 설정 변경 절차를 따르고 개발 쪽에서 임의로 끄지 않는다. 서명을 들일지는 플랫폼이 막는 이 경우에도 고객·계약이 정한다.
- 현장 안내문에 SmartScreen·스마트 앱 컨트롤의 경고 화면과 누를 단추를 적을 때는 공식 문서에 없으므로 실제 PC 에서 본 화면만 적는다.
