# 점검

앱이 바뀌면 기능 지도도 따라 낡는다. 점검은 지도의 기능 하나하나를 소스로 읽고 실제로 조작해 보며 절차를 맞춘다. 단위는 기능이다. 모든 기능을 소스와 실행으로 한 번 이상 덮는다.

## 1. 쓰는 곳

절차 파일, 기능별 파일, 절차가 가진 도움 스크립트만 고친다. 제품 코드는 고치지 않는다. 점검 중 적은 메모(덮은 기능, 닿지 못한 전제, 확인된 낡은 곳)는 임시 자리에 두고 커밋하지 않는다.

## 2. 순서

1. 대상 찾기. 프로젝트 규칙 문서가 가리키는 절차 파일을 연다. 후보가 여럿이면 어느 것인지 묻는다. 없으면 점검을 멈추고 새로 만드는 쪽으로 간다.
2. 목차 맞추기. 기능 지도 목차와 실제 기능 항목을 맞춘다. 빠진 항목, 남는 항목, 겹친 항목, 끊긴 링크를 고친다.
3. 소스 읽기. 기능마다 "이 사용자 기능이 코드에서 어떻게 동작하나"를 읽고, 지도와 다른 곳 후보를 파일·줄 근거와 함께 적고, 실행 확인 경로 하나를 뽑는다. 기능이 많으면 기능마다 읽기 전용 실무 에이전트에게 맡겨 함께 돌린다. 그 에이전트는 앱을 조작하지 않고 파일을 고치지 않는다. 받을 꼴: 기능 요약 · 소스 입구 · 다른 곳 후보(없으면 없음) · 확인 경로 하나.
4. 맞추기. 모든 기능 항목에 요약이 돌아왔는지 본다. 겹치는 확인 경로는 같은 앱 상태에서 이어 돌도록 묶는다. 근거가 붙은 다른 곳 후보만 직접 확인한다. 최근 변경에서 사용자에게 보이는데 지도에 없는 기능을 찾고, 그 기능의 소스 경로를 댈 수 있을 때만 빠졌다고 적는다.
5. 실행 확인. 소스가 깨끗해 보여도 돌린다. 조작은 한 쪽이 맡는다. 띄우는 방식은 절차의 실행 절을 따른다(서버·화면 앱은 오래 띄운 하나를 차례로, 짧은 CLI 는 실행마다 새 자리). 모든 기능을 한 번 이상 조작하고, 처음부터 끝까지 아래 셋을 지킨다.
   - 상태 점검을 첫 조작 전, 새 세션마다, 실패한 조작 뒤마다 돌린다. 프로세스는 살아 있는데 화면이 굳은 상태처럼 상태 점검으로 안 보이는 고장은 알려진 상태로 되돌리거나 다시 띄운다.
   - 지금까지 남긴 증거가 모든 정리 뒤에도 그 폴더에 있는지 직접 본다.
   - 한 조작이 띄운 것은 그 조작이 끝나면 정리한다. 실패한 시도의 찌꺼기도 정리한다. 함께 쓰는 인스턴스면 찌꺼기만 지우고 인스턴스는 둔다.
6. 가르기(3절)로 판정하고 고친다. 고친 조작 방법은 다시 돌려 확인한 뒤에 반영한다.
7. 마지막 정리는 다시 돌린 확인까지 끝난 뒤에 한 번 한다. 증거는 남긴다.
8. 보고(4절).

상태 점검이 절차가 낡은 탓에 실패하면 그것도 낡은 곳이다. 절차를 고치고, 그 고침으로 무효가 된 것만 다시 띄워 한 번 더 돌린다. 그래도 실패하면 막힘이다.

## 3. 가르기

| 본 것 | 판정 | 할 일 |
|---|---|---|
| 지도 설명이 틀리거나 빠졌고, 제품 변경이 의도된 것 | 문서가 낡음 | 지도를 고친다 |
| 앱은 맞게 동작하는데 절차로 조작하지 못함 | 조작 수단 빈틈 | 절차·도움 스크립트를 고치고 다시 돌린다 |
| 지도대로 동작해야 하는데 다르게 동작하고, 의도된 근거가 없음 | 제품 회귀 | 사용자에게 알린다. 지도는 그대로 둔다 |
| 필요한 전제(로그인, 권한, 운영체제, 외부 서비스 상태)가 없어 닿지 못함 | 닿지 못함 | 빠진 전제와 시도한 경로를 적는다. 지도에 그 전제가 없으면 문서가 낡은 것으로 함께 고친다 |

의도된 변경의 근거로 보는 것:

- 그 동작을 바꾼 커밋 메시지·이슈·변경 설명
- 프로젝트 규칙 문서의 결정 기록
- 같은 변경 안에서 새 동작에 맞춘 화면 문구·도움말·시험이 함께 바뀜

근거가 엇갈리거나 아무 근거도 없는데 바뀐 동작이 더 나아 보이면, 제품 회귀로 보고하고 "의도된 변경이면 지도를 고치겠다"는 선택지를 붙여 사용자에게 묻는다. 사용자와 직접 대화하지 않는 에이전트로 일하면 `올림: 남은 것 · 양쪽 근거 · 추천 · 고르면 달라지는 것` 꼴로 넘긴다.

## 4. 보고

첫 줄에 결과 하나(그대로 · 바뀜 · 막힘)를 쓰고 이어서 적는다.

- 덮은 기능: 기능 ID 마다 소스 확인·실행 확인 여부
- 닿지 못한 기능: 빠진 전제와 시도한 경로
- 고친 곳: 바뀜일 때 고친 파일 목록. 보고 전에 고친 파일을 다시 읽는다
- 제품 회귀: 기능 ID, 지도의 기대, 실제 동작, 증거 위치
- 막힘: 막은 명령·오류·전제

커밋·PR 은 사용자가 요청할 때 고친 파일만 한 묶음으로 만든다.
