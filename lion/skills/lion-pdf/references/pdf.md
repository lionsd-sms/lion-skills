# PDF

## 추출과 글자 인식

- 추출 결과가 비거나 짧으면 원본 쪽을 보고 스캔·암호·글꼴 인코딩·읽기 순서 중 원인을 가린다. 암호 문서는 제공된 자격으로만 연다.
- 텍스트 PDF와 스캔 PDF를 구분한다. 글자 인식은 필요한 이미지 범위에만 언어 데이터를 확인하고 돌린다. 믿을 만한 텍스트 레이어는 그대로 둔다.
- 표·다단·회전·각주·수식은 읽기 순서·행·열·0/O·소수점·부호·한국어 판독을 원본 쪽과 대조한다.
- 글자 인식 결과는 평균 신뢰도가 아니라 독립 기대 행·셀·필수 식별자·단위·합계와 대조해 받아들인다. 표 전체·행·열 누락은 신뢰도가 높아도 생긴다. 실패한 범위는 해상도·언어·분할 방식을 바꿔 그 범위만 다시 돌린다.
- 인식 원문·재실행 결과·근거로 고친 값을 구분해 적는다. 사람이 셀을 나눠 준 시험은 자동 표 구조 인식의 성공이 아니다.

## 보존

- 서명된 PDF를 쪽 편집·재내보내기하면 디지털 서명이 무효가 된다. 서명된 원본을 따로 보관한다.
- 한국어를 만들 때는 글리프를 지원하는 실제 글꼴을 쓰고 임베딩·검색·복사를 확인한다.
- PDF/A·PDF/UA 준수는 전용 검증기를 통과했을 때만 선언한다.

## 양식 값과 표시

- 입력 양식은 필드 이름·유형·계층·선택값·계산·표시 상태와 쪽 Widget의 appearance를 함께 확인한다. XFA·계산 JavaScript 지원은 AcroForm 지원과 별개다.
- 쓰는 라이브러리 판본이 값과 appearance를 함께 갱신하는지 확인한다. 저장 뒤 필드 값과 Widget 표시를 둘 다 검사한다. `NeedAppearances` 설정과 텍스트 추출은 표시 검증이 아니다.
- 평탄화할 때는 모든 값의 appearance를 먼저 그린 뒤 Widget과 필요 없는 필드 트리를 지우고, 평탄화 옵션을 켠 뒤에도 Widget이 남았는지 확인한다.

## 쪽 조립(병합·분할·순서·회전)

- 여러 원본에 이름이 같은 양식 필드가 있으면 필드가 합쳐지거나 값이 바뀌지 않게 구분하고, 결과에서 필드의 이름·값·보이는 모양을 대조한다.
- 링크와 책갈피가 선택에서 빠진 쪽을 가리키는지 확인한다. 그 링크를 없애면 제거된 수와 위치를 결과에서 확인한다.
- 결과의 쪽 수·순서·회전·크기·링크 목적지·책갈피 계층·양식 표시를 원본과 대조한다.

## 본문 한 줄 편집

- 작성 원본이 있으면 원본을 고쳐 다시 내보낸다. 작성 원본이 없고 기존 배치를 지켜야 하는 독립된 한 줄일 때만 직접 편집한다. 스캔, 여러 줄, 여러 텍스트 조각으로 나뉜 문구는 한 줄 편집으로 처리하지 않는다.
- 새 문구가 원본 글꼴의 글리프를 포함하는지, 같은 계열·굵기·크기·색·기준선으로 지정 영역에 들어가는지 확인한다. 들어가지 않으면 주변 배치를 바꾸지 않고 다른 방법을 고른다.
- 옛 글자는 실제 텍스트에서 지운다. 흰 사각형으로 덮지 않는다. 새 사본에서 옛 문구가 검색·추출되지 않고 새 문구가 보이는지 확인한다.

배치는 텍스트 추출이 아니라 렌더링으로 확인한다.
