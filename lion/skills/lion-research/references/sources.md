# 출처 고르기와 기록

## 결정의 까닭

왜 이렇게 정했는지를 물으면 결정한 사람이 남긴 글(회의록, 설계 문서, 커밋 · PR 설명, 이슈)이 1차다. 같은 시기 여러 기록이 같은 쪽을 가리키면 그다음 근거로 쓴다. 지금 결과물의 생김새는 까닭의 근거로 쓰지 않는다.

## 판과 기준 시점

- 프로그램 질문은 대상의 판부터 정한다. 프로젝트가 있으면 의존성 파일(package.json, Cargo.toml, pyproject.toml, go.mod 같은 것)에서 실제 판을 읽는다. 판을 알 수 없고 판에 따라 답이 갈리면 묻는다.
- 문서 사이트는 판 고르기 메뉴와 주소의 판 표시를 확인하고, 질문 대상과 같은 판의 쪽을 읽는다.
- 법령 · 약관은 시행일과 개정 이력을 적는다.
- 도구가 없어 못 본 갈래는 「확인 못 한 것」에 "도구 없음"으로 적는다.

## 공식 출처끼리 어긋날 때

- 둘 다 적고 차이를 한 줄로 쓴다(예: API 참고서와 이전 안내서의 기본값이 다름).
- 날짜 · 판이 더 가까운 쪽, 더 좁게 그 대상을 다루는 쪽에 무게를 두고 그 근거를 쓴다.
- 직접 시험할 수 있는 것(명령 한 줄, 작은 예제)은 대상 판에서 시험해 가린다. 시험 결과도 근거 표에 한 줄로 넣는다.
- 공식 출처와 프로젝트의 기존 방식이 다르면 둘을 나란히 보이고, 어느 쪽을 따를지는 사용자에게 객관식으로 묻는다.

## 예제 코드 옮기기

- 예제 코드 안의 외부 주소(통계 수집·광고 주소)는 결과에 옮길 때 표시해 사용자가 보게 한다.
