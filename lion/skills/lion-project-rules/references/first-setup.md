# 처음 정하기

목차: 1. 묻기 전에 · 2. 틀 질문 · 3. 항목 질문 · 4. 답을 적는 법. 표준화 순서·범위·끝 조건과 항목 분류는 「표준화」 파일이 맡는다.

프로젝트 규칙 문서에 「폴더 틀」 절의 `틀:` 줄이 없고 오래 남을 관례를 정해야 할 때 쓴다: 새 프로젝트의 첫 요청, "표준화해줘", "규칙 정리해줘", 프로젝트 전체 정리. 이미 정해진 답은 다시 묻지 않는다.

## 1. 묻기 전에

1. 사용자가 써 온 틀을 찾는다: 요청에서 말한 틀("내 틀대로", "저번 프로젝트처럼"), 사용자가 가리킨 다른 프로젝트의 AGENTS.md, 저장된 틀 목록의 알아보는 표시와 맞는 틀. 그 사용자의 것으로 드러난 틀만 쓴다.
2. 기존 프로젝트면 코드·문서·커밋 이력에서 지금 관례를 축마다 뽑는다: 폴더, 문서 자리, 실행 파일, 작업 기록, 커밋 꼴, 화면 문구. 찾지 못한 축은 「관례 없음」.
3. 채운 것은 표로 보이고 빈 것만 묻는다. 지금 정할 항목을 위로 올린다.
4. 사용자가 볼 결과와 목적을 개발 용어 없이 먼저 쓴다.

## 2. 틀 질문

써 온 틀을 찾았을 때 한 번 묻는다. 찾지 못했으면 이 절을 건너뛰고 3절로 간다.

- 「폴더 틀」 절에 `틀:` 줄이 틀 이름으로 있으면 묻지 않고 그 틀을 쓴다.
- `틀: 지금 관례`가 적힌 프로젝트에서 "표준화해줘"가 오면 써 온 틀로 바꿀지 한 번 묻는다.
- 요청에서 이미 갈래를 말했으면("내 틀대로", "기본대로"는 가, "틀은 내가 정할게"는 나) 묻지 않고 그 갈래로 간다. 나면 3절 질문을 그 응답에 낸다.

```text
이 프로젝트의 틀을 고르세요. 틀은 폴더·문서·실행 파일·작업 기록·화면 문구의 모양입니다. 답은 AGENTS.md에 적고 다시 묻지 않습니다.
가. <써 온 틀 이름> 그대로 (추천). 예: 코드는 app/, 문서는 docs/ 아래 번호 영역, 커밋 첫 줄 `fix: TASK-2026-10-19-1 한 줄`, 화면은 값과 동작만
나. 항목마다 정하기. 네 가지를 이어서 여쭙니다
다. 지금 관례대로. 예: <뽑은 관례. 새 프로젝트면 「프레임워크가 만드는 모양 그대로」>
쓰시는 다른 틀이 있으면 고르는 대신 알려 주세요.
```

## 3. 항목 질문

써 온 틀이 없을 때, 또는 틀 질문에서 나를 골랐을 때 낸다. 한 응답에 묶어 최대 넷. 추천을 첫째 선택지로 두고 실제 예를 붙인다.

```text
이 프로젝트에서 계속 지킬 규칙을 정합니다. 답은 프로젝트 맨 위 AGENTS.md에 적어 두고 다시 묻지 않습니다.
번호와 가·나·다로 답해 주세요. 「모두 추천대로」도 됩니다. 예: 1가 2다(설명 조금 허용) 3가 4나
1. 폴더와 문서 자리
   가. <추천 값> (추천). 예: <실제 예>
   나. 프레임워크가 만드는 모양 그대로. 예: src/, README 하나
   다. 직접 말하기
2. 화면 문구
   가. <추천 값> (추천). 예: 값과 버튼만, 오류는 「저장 · 실패」
   나. 설명과 도움말을 화면에 넉넉히
   다. 직접 말하기
3. 커밋과 작업 기록
   가. <추천 값> (추천). 예: fix: TASK-2026-10-19-1 목록이 비면 새 항목 단추를 보인다
   나. 영어 Conventional Commits, 작업 기록은 커밋으로
   다. 직접 말하기
4. 미리 묻고 할 일
   가. 새 라이브러리 들이기와 배포만 묻기 (추천)
   나. 커밋도 묻기
   다. 직접 말하기
```

- 추천 값: 써 온 틀이 있으면 그 틀의 값. 없으면 1번 「프레임워크가 만드는 모양 그대로」, 2번 「짧은 라벨과 값 위주, 설명은 꼭 필요한 곳만」, 3번 「지금 커밋 꼴, 긴 작업만 작업 기록 문서」.
- 기존 프로젝트면 각 문항에 「지금 관례대로: <뽑은 관례>」를 선택지로 넣는다.
- 요청에서 이미 답한 문항은 빼고 번호를 다시 매긴다.
- 4번은 지금보다 조심하는 쪽으로만 바꾼다. 더 느슨한 답이 오면 그 문항만 다시 묻는다.
- 알아볼 수 없는 답은 그 문항만 다시 묻는다. 일부만 답이 오면 받은 것만 적고 빠진 문항은 추천대로 두고 끝 보고에 적는다.

## 4. 답을 적는 법

| 답 | 「폴더 틀」 절에 적을 것 | 할 일 |
|---|---|---|
| 써 온 틀 | `틀: <틀 이름>` | 새 프로젝트는 처음부터 그 틀대로 만든다. 표준화는 그 틀로 옮긴다 |
| 항목마다 정함 | `틀: 이 프로젝트에서 정함`, 추천과 다른 항목만 `항목: 값` 줄로 | 적힌 항목은 그 값, 적히지 않은 항목은 추천 값을 따른다 |
| 지금 관례 | `틀: 지금 관례`, 뽑은 관례와 근거 파일·커밋 | 옮기지 않는다 |
| 사용자가 알려 준 틀 | `틀: <사용자가 말한 이름>`, 그 틀의 항목을 한 줄씩 | 그 틀이 정하지 않은 축은 일반 관례가 채운다 |

- 기존 프로젝트면 `틀:` 줄 끝에 범위를 붙인다: `· 범위: 앞으로 하는 일만 | 빈 곳만 | 전체 정리`.
- 사용자가 고른 답은 「정해진 결정」에도 날짜와 함께 적는다.
