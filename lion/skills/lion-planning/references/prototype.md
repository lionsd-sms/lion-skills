# 시안으로 고르기

말로 물어서 고르기 어려운 결정(화면 배치, 정보 밀도, 조작 흐름, 상태가 바뀌는 규칙)은 버릴 시안을 만들어 사용자가 보고 고르게 한다.

## 만들지 판단

- 시안이 가를 결정을 한 문장으로 먼저 쓴다. 가를 결정이 없으면 만들지 않는다.
- 프로젝트에 같은 종류의 선례가 있으면 선례를 따르고 시안을 만들지 않는다.
- 보이는 결과가 같은 내부 방법은 AI가 정한다. 시안은 보이는 결과가 갈리는 결정에만 쓴다.
- 방향이 열려 있으면 비슷한 기존 제품·화면 사례를 모아 방향부터 고르게 한 뒤 시안을 만든다.

## 두 갈래

| 가를 질문 | 시안 꼴 |
|---|---|
| 어떻게 보여야 하나 | 화면 시안 |
| 규칙 · 상태 변화가 맞나 | 규칙 시안 |

질문이 어느 쪽인지 갈리지 않으면, 대상이 화면이면 화면 시안, 처리 규칙이면 규칙 시안으로 하고 시안 맨 위에 그렇게 고른 까닭을 적는다.

### 화면 시안

- 2~3개. 배치 · 정보 순서 · 주된 조작이 서로 다르게 만든다. 색이나 간격만 다른 시안은 다시 만든다.
- 기존 화면이 있으면 그 화면 안에서 실제 머리글 · 메뉴 · 자료와 함께 보이게 한다. 빈 화면 위에서는 모든 시안이 괜찮아 보여 고르기 어렵다.
- 버튼이나 키 하나로 시안을 바꿔 보게 하고, 시안마다 이름표를 붙인다.

### 규칙 시안

- 브라우저로 여는 HTML 파일 하나로 만든다. 설치나 서버 없이 두 번 눌러 열린다.
- 화면 구성, 위에서 아래로:
  1. 제목과 이 시안이 확인하는 질문 한 줄
  2. 지금 상태: 이름 붙은 칸으로 보인다. 누를 때마다 다시 그리고 방금 바뀐 칸을 표시한다
  3. 동작 버튼: 언제든 아무 순서로 누른다
  4. 장면 탭: 정상 흐름, 까다로운 경계, 막혀야 하는 시도. 장면마다 같은 처음 상태에서 시작하고 누를 순서를 버튼으로 둔다
- 버튼과 칸 이름은 업무 말로 쓴다.
- 규칙 부분은 화면 코드와 떼어 입력과 상태만 받는 함수로 둔다. 고른 뒤 실제 코드로 그대로 옮길 수 있다.

## 공통

- 제품 코드와 떨어진 곳에 두고, 이름에 시안임을 드러낸다.
- 시험 · 저장 · 오류 처리 · 추상화를 넣지 않는다. 저장 방식 자체가 질문일 때만 이름에 「시안 · 지워도 됨」을 붙인 임시 파일을 쓴다.
- 보이기 전에 직접 열어 화면을 찍거나 동작을 돌려 본다.
- 보일 때 담는 것: 만든 시안, 증거(화면 사진 · 출력), 시안마다 고르면 달라지는 것, 추천, 시안 위치. 시안은 버릴 것이라고 밝힌다.

## 고른 뒤

- 고른 결정과 그 결정이 답한 질문을 계획과 결정 기록에 적는다.
- 실제 구현에는 고른 결정만 옮긴다.
- 시안 파일은 제품 코드 밖에 근거로 남긴다.
