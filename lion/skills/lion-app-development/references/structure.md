# 코드 크기와 구조

## 1. 크기 재기

- 기본 단위는 프로젝트의 정상 서식을 적용한 물리 소스 줄에서 빈 줄과 주석만 있는 줄을 뺀 수다. 코드 뒤에 주석이 붙은 줄은 코드로 센다. 전체 물리 줄 수도 함께 보인다.
- 언어에 맞는 구문 분석기나 확인된 기존 계측 도구로 잰다. 주소·정규식·문자열·템플릿·문서 문자열을 단순 정규식으로 주석처럼 지우지 않는다. 정확히 재지 못하면 전체 줄만 보이고 측정 필요로 둔다. 세기 실패를 0으로 바꾸지 않는다.
- Vue·Svelte 는 단일 파일 구성요소 전체와 스크립트·템플릿·스타일 구역을 함께 잰다. 작은 스크립트만 골라 전체가 작다고 하지 않는다.
- 프로젝트가 정한 크기 기준이 없으면 숫자를 새로 강제하지 않고 응집·결합·반복 수정 부담으로 판단한다. 기준 이하라고 검토를 면제하지 않는다.

## 2. 나눔·합침을 받아들이는 기준

- 요구 하나를 고칠 때 이해할 범위가 줄었나. 나눔이 내부 상태 노출·인자 묶음·순환 의존·감싸는 층·함께 바뀌는 파일을 늘렸나.
- 줄 수 감소만으로 받아들이지 않는다. 책임 없는 분할·주석과 시험 삭제·압축으로 얻은 감소는 완료 근거가 아니다. 예: 520줄을 260줄 둘로 나눠 결합이 더 강해졌으면 거절하고, 280줄에 로그인·결제·저장이 섞였으면 더 조사한다.
- 초과 파일을 그대로 두면 왜 응집됐는지와 다시 볼 조건을 남긴다. 길이 상위 몇 파일만 처리하고 전체 완료로 보고하지 않는다.

## 3. 구조 개선 후보 찾기

- 사용자가 정한 방향이 없으면 최근 커밋에서 자주 바뀐 곳부터 보고, 의심 모듈마다 삭제 시험(모듈을 지운다고 생각해 복잡도가 사라지면 껍데기, 호출처 여러 곳에 다시 나타나면 제 몫을 함)을 한다.
- 후보마다 `파일 | 문제 | 바꿀 것 | 나아지는 점(고칠 곳이 한곳에 모이나, 시험이 공개면으로 되나) | 추천 강도(강함 · 볼 만함 · 추측)` 을 적고 가장 먼저 할 하나를 추천한다. 후보가 모두 「추측」이면 「뚜렷한 후보 없음」으로 보고한다.
- 인터페이스 설계는 사용자가 후보를 고른 뒤에 한다. 프로젝트 규칙 문서의 정해진 결정과 부딪치는 후보는 마찰이 실제로 클 때만 그 사실을 밝혀 올린다.

## 4. 폴더 정리

- 조치(유지 · 옮김 · 이름 바꿈 · 합침 · 지움 · 보류)와 상태(미확인 · 판정 · 적용 · 검증)는 다른 축으로 적는다.
- 역할을 모르는 폴더는 보류로 두고 무엇을 모르는지 적는다.
- 보관 폴더로 옮긴 뒤 참조가 모두 새 경로를 가리키는지와 원래 자리가 하던 역할이 어디로 갔는지까지 확인한다.
