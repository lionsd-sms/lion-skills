# 호환·다시 돌리기·줄이기·옛 API

## 1. 저장 형식과 겉으로 보이는 계약

- 저장 형식·설정·명령·파일 형식을 바꾸면 예전 것을 읽거나 옮기는 길을 함께 만들고 예전 자료로 확인한다.
- 여러 PC 의 앱이 같은 자료(공유 폴더의 DB·설정 파일)를 쓰면 옛 판과 새 판이 함께 여는 기간이 있다. 새 판은 옛 판이 읽을 수 있는 꼴로 더하기만 하고, 칸 지우기·이름 바꾸기는 모든 PC 가 새 판이 된 뒤 따로 낸다.
- 문서에 없어도 겉으로 보이는 동작은 계약이다. 내보내는 파일의 열 순서·열 이름·파일 이름 꼴·날짜 꼴·정렬은 사람의 엑셀 작업과 다른 프로그램이 기댄다. 요청한 것만 바꾸고 새 열은 끝에 더하며, 바뀐 겉모습은 끝 보고에 적는다.

## 2. 다시 돌려도 같은 끝

상태를 바꾸는 작업(명령, 예약 작업, 설치·갱신, 처리 반복)은 몇 번 돌거나 어디서 멈췄어도 같은 끝 상태로 모이게 만든다.

- 지난 실행이 하려던 것보다 지금 있는 상태를 읽고 목표와의 차이만 적용한다.
- 실행이 남기는 잠금·임시 파일·반쯤 쓴 기록·잡아 둔 일은 다음 실행이 낡았는지 판별할 수 있게 만든다. 임시 경로에 쓴 뒤 이름을 바꿔 넣고, 산출물끼리는 내용으로 견준다.
- 확인: 연달아 두 번 돌리면 어떻게 되나, 지난 실행이 아무 지점에서 죽었다면 어떻게 되나, 다시 돌려 같은 끝에 닿나. 남은 상태에 따라 답이 갈리면 맞추기 단계를 더한다.

## 3. 동작을 지키며 줄이기

- 500줄이 넘는 기계적 변경은 스크립트·코드 변환 도구로 한다.
- 까닭이 안 보이는 분기·예외 처리·감싸개를 지우기 전에 그 줄의 Git 이력과 연결된 문서에서 생긴 까닭을 찾고, 그 까닭이 아직 걸리면 남긴다.
- 단순화는 읽는 사람이 붙들 개념 수와 따라갈 층 수로 판단한다. 개념에 이름을 준 도우미를 펼치거나 무관한 논리를 한 함수로 합치는 것은 단순화로 치지 않는다. 어디서도 읽는 부담을 줄이지 못한 정리는 되돌린다.

## 4. 옛 API 걷기

- 외부 소비자(공개 API·독립 배포 클라이언트·플러그인·다른 팀)가 없는 내부 API는 호출처를 모두 옮기고 옛 API를 같은 변경에서 지운다. 호환층이나 옛·새 병행 경로를 남기지 않고, 옛 구현 세부만 지키던 시험은 새 계약을 단언하는 시험으로 바꾼다.
- 외부 소비자가 있어 점진 이행을 하면 계약에 마감일이 있을 때 그것을 쓰고, 그 밖에는 `v1 consumer usage = 0` 처럼 잴 수 있는 종료 조건을 적는다. 종료 조건을 채운 임시 장치는 정리한다.
