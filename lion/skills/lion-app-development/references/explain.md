# 설명 질문

"이거 어떻게 돌아가?", "이 기능은 어디에 둬야 해?"처럼 읽기만 하는 질문은 코드를 바꾸지 않고 설명으로 끝낸다.

- 한 모듈·좁은 질문은 바로 읽고 설명한다. 여러 파일·서비스에 걸친 하위 체계는 갈래(진입·자료·상태·외부 연결 따위) 둘에서 넷으로 나눠 읽고 한 그림으로 합친다. 범위가 애매하면 좁게 잡은 해석을 밝히고 시작한다.
- 설명 차례: 무엇이고 왜 있나 → 핵심 개념 → 흐름(무엇이 시작하고 차례로 무엇이 일어나며 자료가 어디로 가나) → 손댈 파일·함수 자리 → 놓치기 쉬운 점. 해당 없는 절은 뺀다. 파일·함수 이름을 대고 흐름은 문장으로 쓰며 코드는 꼭 필요한 조각만 붙인다. 여러 부품이 주고받으면 그림 하나를 붙인다. 읽고도 모르는 것은 모른다고 적는다.
- 대안 사이의 결정을 묻는 질문은 비교표와 추천으로 답한다. 질문의 전제가 틀렸으면 근거와 함께 그렇게 말한다.
- 읽다가 고칠 일이 드러나면 고치기 전에 무엇을 고칠지 알리고 요청 범위를 확인한다.
