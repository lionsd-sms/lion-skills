# 소스 인계

다른 개발자·조직에 소스를 넘길 때 쓴다.

## 1. 인계 유형

- 저장소 접근권: Git 기록·브랜치·이슈와 함께 저장소 권한을 넘긴다.
- 소스 사본: 특정 커밋·판의 파일 묶음을 넘긴다.
- 빌드되는 묶음: 사본에 필요한 문서·설정·자원·도구·스키마·전환 자료를 더해 받는 쪽이 재현하게 한다.

사용자가 안내 글만 청하면 안내 산출물 범위에서 끝내고, 묶음 만들기·보내기는 따로 청할 일로 다룬다. 커밋하지 않은 상태는 그대로 보존하고, 사본의 기준이 지금 작업 트리면 인계 안내에 그렇다고 적는다.

## 2. 넘기기 전 점검

- 개인 절대 경로와 개인 계정 정보
- 실제 사용자·운영 데이터베이스 덤프와 개인정보
- 캐시·임시 파일·로그·충돌 덤프와 개인 개발 도구 상태
- 저장소 밖 로컬 파일을 가리키는 심볼릭 링크·복사
- 대용량 의존성·빌드 출력을 다시 만들 수 있는지
- 외부 부품의 라이선스·고지·출처 표시 의무

민감 자료는 안전한 전달 경로와 따로 정한 주인으로 분리한다. 다시 만들 수 있는 산출물에는 생성 명령, 소스 판 경계, 결과를 가르는 의존성·도구·구성, 산출물 식별값을 함께 적는다.

## 3. 인계 안내

전달본 루트에 인계 안내를 두고 루트 README에서 잇는다. 안내에서 다음을 찾을 수 있게 한다.

- 무엇을 넘겼고 항목마다 역할은 무엇인가
- 어느 판·커밋이 기준인가
- 처음 무엇을 읽는가
- 빌드·실행·시험 방법은 어디 있는가
- 설정·비밀값은 어디서 받는가
- 자원·자료·도구·외부 의존은 어디 있는가
- 전환·배포·알려진 한계는 어디 있는가
- 무엇을 검증했고 어느 부분이 확인 못 함인가. 받는 쪽에서 이어 갈 수 있는지 확인하지 못했으면 그것을 확인 못 함으로 남긴다

넘기기 전에 역할 목록과 실제 묶음·파일 목록, 적은 경로·연결, 넘긴 판·빌드 표시와 안내 문구가 맞는지 전달본 자체로 확인한다. 위험에 맞게 설치·빌드·시험의 핵심 경로를 깨끗한 별도 자리에서 재현한다.
