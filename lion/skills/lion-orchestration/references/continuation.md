# 이어가기

## 실행 상태

실행 상태는 셋으로 가른다: 실행 안 함, 실행했으나 결과 모름, 일부 끝남. 중간 결과를 완성본으로 넘기지 않는다. 내보낸 실행은 끝날 때 끝남 · 버림 · 늦게 와서 맞춰 봄 가운데 하나로 모두 정리한다.

## 살아 있나 보기

도는 실행을 확인하려고 그 실행을 이어 부르지 않는다. 이어 부르면 쉬던 실행이 다시 돈다. 반환 파일, 작업 사본의 커밋, 호스트의 실행 목록처럼 읽기만으로 본다.

같은 몫을 새 실행에 다시 맡기기 전에 버릴 실행을 멈추고 멈췄는지 확인한다. '끝남' 알림은 멈춤의 근거로 쓰지 않는다. 작업 사본의 변경(git 상태)이 그 실행의 반환과 어긋나거나 계속 바뀌면 아직 도는 것으로 본다.

## 다시 시도

실패 갈래마다 다르게 한다.

| 실패 | 다시 하는 법 |
|---|---|
| 한도·메모리 초과 | 범위를 줄여 새로 보낸다 |
| 연결 끊김 | 그대로 다시 보낸다 |
| 도구 오류 | 다른 모델로 보낸다 |
| 까닭 모름 | 한 번 다시 보낸다 |

두 번 다시 해도 안 되면 그 단위를 버림으로 두고 나머지 계획을 그것을 빼고 다시 짠다. 마스터 자신의 도구 실패도 같은 한도를 둔다. 몇 번 잇달아 실패하면 멈추고, 끝낸 것 · 있는 곳 · 다시 시작할 정확한 명령을 파일에 남긴 뒤 보고한다.

잘못된 앞 결과나 깨진 확인 기준 때문에 내보내는 몫마다 쓸모없는 결과가 나오면 상시 지시 목록 맨 위에 멈춤 줄을 쓰고, 도는 실행은 끝나게 둔 채 원인을 고친 뒤 줄을 지운다.

## 기준이 바뀔 때

- 무효가 된 결과는 늦게 와도 합치지 않는다. 늦게 온 결과는 지금 판본과 대조하고, 쓸 만한 발견만 새 몫으로 다시 맡긴다.
- 취소한 담당이 띄운 하위 실행도 멈춘다. 멈췄는지 확인하지 못한 실행의 결과는 합치지 않고 남은 실행과 영향을 보고한다.

## 재개

호스트가 다시 시작되면 상시 지시 목록과 단위 기록을 다시 읽고, 도는 실행은 실행 번호 대신 브랜치 · 결과 파일로 다시 찾는다. 결과나 인계를 잃은 단위는 검수 안 됨으로 둔다.
