# 긴 지휘

여러 시간 걸리는 일, 단위가 수십 개인 일, 사용자가 자리를 비우고 나중에 결과를 보는 일에 쓴다. 한 에이전트가 정한 시간 안에 끝낼 수 있으면 이 장치들을 접고 바로 하거나 맡김으로 한다.

## 시작 전에

- 완료 조건을 확인할 수 있는 문장으로 쓴다. 셀 수 있으면 센다(예: 단위 40개 모두 합침, 각 단위 시험 통과).
- 범위를 수로 적는다: 단위 수, 대략의 시간, 시작 전에 드러난 걸림돌.
- 엄격함을 정한다. 되돌리기 어렵거나 파급이 큰 단계에는 확인 관문과 남길 증거를 더 두고, 되돌리기 쉬운 단계에는 덜 둔다.
- 확인 장치를 일보다 먼저 만든다. 바꾸기 전 상태에서 기준값을 잡아 두어 "전 값 대 새 값"으로 읽히게 한다.
- 위험한 미지부터 순서를 둔다. 뼈대와 확인 장치가 기능보다 먼저다.
- 이 틀(완료 조건 · 범위 · 엄격함 · 단계 목록)을 사용자에게 한 번 보이고, 되돌리기 쉬운 준비는 답을 기다리지 않고 진행한다.

## 상시 지시 목록

번호를 붙인 제약을 한 줄에 하나씩 적은 파일을 하나 둔다: 모델 고르는 기준, 확인 기준, 손대지 않을 경로, 올림 기준처럼 모든 몫이 지킬 것. 모든 지시서와 이어 부르기에 그대로 붙인다. 같은 지시를 두 번째로 말하게 되면 말하기 전에 목록에 먼저 더한다.

## 돌리는 동안

- 단위마다 가설 → 가장 작은 변경 → 실제 대상에서 완료 조건으로 측정 → 나아졌으면 남기고 아니면 되돌림. 다음 단위는 앞 단위 확인이 끝난 뒤 시작한다.
- 도움이 될지도 모르는 덧댐은 진전을 보이지 못하면 되돌린다.
- 확인은 결과물을 직접 보고 한다. 너무 쉽게 통과하면 시스템보다 관찰 방법을 먼저 의심한다. 작업자가 확인 관문을 피해 갔으면 약속을 단단히 고쳐 다시 보낸다. 관문 자체가 틀렸으면 관문을 따로 고친다.
- 정체는 멈출 까닭이 되지 않는다. 방법을 바꿔 계속한다. 정말 막다른 곳이면 그 사실을 보고한다. 끝냈다고 하려고 완료 조건을 느슨하게 하지 않는다.
- 도중에 본 것은 진행을 막는 것만 고치고 나머지는 남은 것에 모은다.
- 사용자가 맡기고 자리를 비운 동안 나온 사용자 결정 가운데 되돌리기 쉬운 것은 추천안으로 진행하고 실행 일지에 적는다. 끝 보고에 정한 값과 바꾸려면 할 말을 쓴다. 되돌리기 어려운 결정은 그 결정에 묶인 몫만 세우고 돌아올 때 묻는다.
- 단위 결과는 끝나는 즉시 파일·커밋 등 에이전트 밖에 남긴다. 한 실행 안에만 있는 결과는 끝난 것으로 세지 않는다.
- 사용자가 정한 시간·비용 한도의 7할쯤에 이르면 새 몫을 내지 않고 확인된 것을 합친다.

## 실행 일지

사용자가 자리를 비우는 일은 결정마다 한 줄을 남기는 일지를 작업 폴더에 둔다. 칸은 시각 · 단계 · 결정 · 까닭 · 근거 위치 · 결과. 근거 칸은 커밋·`파일:줄`·결과 파일 경로만 쓴다.

- 덧붙이기만 한다. 틀린 줄은 고치거나 지우지 않고 바로잡는 새 줄을 더한다.
- 모든 동작을 적지 않는다. 갈림길 선택, 확인을 마친 단위, 방향 바꿈·되돌림과 그 계기, 드러난 걸림돌, 고친 관문을 적는다.
- 다른 실행이 같은 일지에 이어 쓰면 첫 줄 단계를 `시작`으로 두고 앞선 줄의 범위를 적는다.
- 기본은 커밋하지 않는 작업 파일이다. 결과를 믿으려면 일지가 필요한 일이면 사용자에게 커밋 여부를 묻는다.
- 끝내기 전에 일지를 실제로 일어난 일과 대조한다. 줄마다 근거가 열리고 주장대로인지 보고, 빠진 갈림길은 더한다.
- 끝 검수를 맡길 때 실행 일지도 검수자가 받을 자료에 넣는다.

## 끝낼 때

완료 조건을 확인 장치와 실제 제품 양쪽에서 확인한다. 실행 중 두 번 이상 바로잡은 것은 상시 지시 목록이나 검사·스크립트로 남긴다. 보고에는 설계한 단계 목록, 고른 엄격함과 까닭, 일지 위치, 완료 조건 대비 확인된 것, 남은 것을 쓴다.
