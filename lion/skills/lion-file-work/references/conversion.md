# 변환과 반복 처리

## 손실 약속

1. 변환 목적(편집·배포·분석·보관)을 요청에서 정한다.
2. 텍스트·표·그림·수식·주석·노트·링크·매크로·읽기 순서·접근성·서식 중 지킬 요소를 정한다. 출력 형식이 지원하지 못하는 요소는 시작 전에 손실로 알린다.
3. 확장자와 시그니처를 대조하고 변환기의 입력·출력 필터를 확인한다. 확장자만 바꾸는 것은 변환이 아니다.
4. 서로 다른 중요한 구조를 담은 사본 하나로 먼저 시험하고 내용·수량·합계·배치·객체를 대조한다. 통과하면 같은 설정으로 나머지를 처리한다.
5. PDF→Word, HTML→PPTX 같은 역변환은 원본 편집 구조를 되살리지 못한다고 미리 알린다.

필드·수식·매크로·차트·복잡한 배치를 지켜야 하는 Office·ODF·구형 형식 변환은 원본 응용프로그램 자동화나 실제로 검증한 변환기로 한다.

## 반복 처리와 복구

- 입력별 해시·출력 대응·처리 상태·검증 결과를 스킬 폴더 밖의 이번 작업 기록에 남긴다.
- 파일마다 별도 작업 사본과 출력 위치를 쓴다. 한 출력 경로에는 한 작업만 쓴다. 입력이 바뀌면 그 입력은 다시 처리한다.
- 실패한 입력과 성공한 출력을 나눈다. 실패 출력은 배포에서 빼고 입력·로그는 남긴다.
- 재시도는 잠금·일시 연결 오류처럼 회복되는 원인에만 한다. 같은 입력·옵션으로 다시 돌려도 나는 오류는 입력·도구·설정을 고친다.
- 중단 뒤에는 검증된 결과를 다시 쓰고 미처리·실패 단위부터 잇는다.
