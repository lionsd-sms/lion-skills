# 결과 검증

실제 산출물의 내용·계산·구조·렌더링·호환을 검사한다.

## 검사 고르기

| 바꾼 것 | 할 검사 |
|---|---|
| 문구·내용 | 원문과 뜻·수치·조건·예외·요구 항목을 대조한다. |
| 기존 파일 편집 | 변경 범위 밖의 내용·서식·객체와 입력 해시를 대조한다. ZIP 패키지 형식은 아래 패키지 구조 검사도 한다. |
| 쪽·슬라이드·차트·글꼴·배치 | 아래 렌더링 범위에 따라 최종 결과를 실제 크기로 확인한다. |
| 형식 변환 | 입출력의 내용·순서·객체·링크·수식·편집성·시각 결과를 시작 전에 알린 손실과 대조한다. |
| 같은 내용의 여러 형식·여러 문서 | 서로의 값·순서·수량·행 수·합계·분류 이름을 대조한다. |

필수 단위 목록과 결과를 하나씩 맞춰 누락을 찾는다.

비교·대조 스크립트를 처음 쓰면 잡아야 할 차이마다 일부러 틀린 사본을 하나씩 만들어(합계 하나 바꾸기, 두 행 맞바꾸기) 스크립트가 각각 잡는지 본다. 입력이 빠졌거나 읽지 못한 칸이 있으면 대조 결과를 '결론 못 냄'으로 낸다.

## 렌더링 범위

- 새로 만들거나 전체 변환·공통 스타일·테마·마스터·글꼴·쪽 크기를 바꾼 결과는 모든 쪽·슬라이드를 확인한다.
- 영향이 국소적인 편집은 바뀐 쪽·슬라이드와 연결된 결과를 확인하고, 전체 개수·순서·구조와 범위 밖 내용·객체가 보존됐는지 대조한다. 구조 대조는 모든 쪽의 시각 검사와 구분한다.
- 작은 문구 수정도 줄바꿈·표 높이·쪽 나눔·목차·공유 객체에 영향을 주면 이어지는 범위까지 넓힌다. 영향 범위를 가를 수 없거나 원본 보존 대조에서 예상 밖 변화가 나오면 전체를 확인한다.
- 명시된 납품·프로젝트 검사 범위가 있으면 그 요구도 따른다.

## 렌더링에서 볼 것

- 글꼴 대체·읽기 순서·표 병합·작은 캡션·각주·한국어 금칙과 줄바꿈.
- 잘림·겹침·넘침·쪽 나눔.
- 긴 표는 쪽마다 머리행이 반복되는가. 표가 쪽을 넘길 때 한두 행(합계 행 포함)만 따로 넘어가지 않았는가. 짧은 표는 한 쪽에 모여 있는가.
- 제목·식별자가 첫 문단과 같은 쪽에 있는가. 문단 끝 한 줄만 다음 쪽으로 넘어가지 않았는가.
- 목차의 순서와 중복.
- 확인란·서명란처럼 정해진 쪽에 있어야 할 요소는 내용을 바꿀 때마다 다시 렌더링해 그 쪽에 남았는지 본다.
- 쪽 배치를 고친 뒤에는 영향받은 절·표의 모든 행·각주·부록·내부 링크·합계를 다시 대조한다.

접근성이 필요한 출력은 제목 구조·대체 텍스트·표 머리·읽기 순서·명도 대비·PDF 태그의 지원과 결과를 따로 확인한다.

## 검사 결과의 범위

- 검사 통과는 그 검사 조건에서의 결과다. 내용·디자인의 완성과 원본 프로그램 호환은 따로 판정한다. 패키지가 열리는 것만 확인했으면 내용 정확성·화면·호환은 미검증이다.
- 구조 검사·호환성·화면 품질을 따로 판정해 보고한다.
- 렌더러가 없거나 실패하면 구조·내용 검사를 이어 하고 시각 품질은 미검증으로 보고한다. 따로 그린 그림은 렌더링 증거가 아니다.
- 중간 판본과 최종본을 구분해 전달한다.

## 패키지 구조 검사

DOCX·PPTX·XLSX·XLSM처럼 ZIP 안에 여러 객체가 든 파일은 원본과 결과의 항목 목록·해시·관계·콘텐츠 타입을 비교한다. 의도한 변경 항목과 예상 밖 변경 항목을 구분하고, 수식·이미지·필드·주석·외부 링크·매크로·차트·슬라이드 마스터 같은 보존 요소가 줄지 않았는지 확인한다.

구조 검사 통과는 파일 내용의 정확성이나 원본 응용프로그램에서의 열림·화면 품질을 증명하지 않는다. ODF·HWPX·EPUB의 ZIP/XML 목록 검사는 해당 형식의 의미·명세 검증과 구분한다.

기존에 있던 결함과 새로 생긴 결함을 구분한다. 항목 수나 해시가 같아도 내용의 뜻·수식 결과·시각 배치가 맞는지는 실제 파일을 다시 열어 확인한다. 도구가 검사 범위를 제한하거나 입력을 처리하지 못했으면 손상으로 단정하지 않고 다른 적합한 도구로 확인한다.

## LaTeX

- `shell-escape`는 끈 채로 컴파일한다.
- 컴파일 완료는 도구가 성공을 돌려줬을 때만 보고한다. 미해결 참조·누락 글리프·넘침 경고와 최종 PDF를 함께 확인한다.

## 오류 수정

문제를 내용·계산·패키지·렌더링·호환성으로 나누고 원인에 맞는 최소 수정을 한다. 고친 뒤 실패했던 검사와 영향받은 결과·연결을 다시 돌린다. 시각 검사 뒤 다시 저장했으면 최종 판본을 다시 확인한다.
