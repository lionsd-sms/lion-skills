# PPTX·PPT·ODP·HTML 슬라이드

## 편집과 보존

- PPTX는 기존 개체를 찾아 고친다. 좁은 편집은 해당 개체만 고친다. 덱 전체를 다시 만든 것은 좁은 편집의 완료가 아니다.
- PPT·ODP는 호환 프로그램이나 검증한 변환기로 사본을 처리한다. PPTX 라이브러리로 열기 전에 그 형식 지원을 확인한다.
- 반복 서식은 제목·본문·캡션·표·주석 같은 역할별로 적용한다. 대량 변경은 역할이 다른 대표 슬라이드로 먼저 검증한 뒤 전체로 넓힌다. 겹침 검사에는 고치지 않은 요소도 넣는다.
- 이미지 경로·임베딩·패키지 관계를 확인하고, 미리보기의 이미지가 내보낸 파일에도 들어갔는지 검사한다.

## 차트

- 차트 데이터를 바꾸면 내장 워크북·차트 캐시·계열과 연결 표·요약이 같은 값인지 저장 뒤 다시 열어 확인한다. 내장 워크북은 지원 API의 활성화 순서대로 연다.
- 숫자와 표시 형식은 따로 깨진다. 원자료 셀·데이터 레이블·축의 표시 형식(원 단위·퍼센트·소수점·천 단위 구분)을 따로 대조한다. `sourceLinked`와 캐시 표시 형식은 다른 값이다.
- PPT·ODP 왕복은 네이티브 차트가 OLE·그림으로 바뀌는지와 레이블·축·글꼴 손실을 확인한다. 같은 모습으로 열리는 것은 편집성의 증거가 아니다.

## 자동화 함정

| 조건 | 대응 |
|---|---|
| 한글·영문 혼합 글꼴 | DrawingML의 `latin`(영문)·`ea`(한글)·`cs`를 따로 다루고 실제 표시 글꼴과 나눠 검사한다. COM `Font.NameAscii`·`NameOther`는 혼합 서식 범위에서 매핑이 뒤바뀐다. 글꼴 편집은 XML에서 하고 COM은 측정·렌더링에만 쓴다. |
| DrawingML 글꼴 요소 삽입 | 스키마 순서 `latin` → `ea` → `cs`로 넣는다. 순서를 어기면 PowerPoint가 파일을 거부한다. |
| COM run 순회 중 서식 변경 | 서식을 바꾸면 run이 합쳐져 `Runs(k,1)` 인덱스가 밀리고 일부만 조용히 적용된다. `(시작 위치, 길이)`를 먼저 다 읽어 두고 문자 위치로 적용하거나 XML에서 편집한다. |
| XML 글 변경 뒤 상자 높이 | `Shape.Height`는 옛 값 그대로라 넘침을 알려 주지 않는다. `TextRange.BoundHeight`(실제 그려진 글자 높이)나 렌더링으로 잰다. |
| COM `TextFrame2`·`TextRange2` 접근 실패 | pywin32 late binding에서 수집 미지원 오류가 난다. `TextFrame.TextRange` 경로나 XML을 쓴다. |
| HTML 슬라이드 | 외부 CSS·폰트·차트·이미지의 접근성과 출력 환경을 확인한다. 렌더링 완료는 실제로 렌더링해 본 뒤에만 보고한다. |

## 확인

- 테마·마스터 변경은 이를 공유하는 슬라이드까지 렌더링 범위에 넣는다.
- 자동 기하 검사가 잡은 겹침은 렌더링으로 의도한 겹침인지 결함인지 가린다.
