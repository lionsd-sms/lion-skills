# 비밀값과 인증

## 무엇이 하드코딩인가

설정값은 실제 프로젝트의 설정 원본 · 환경별 우선순위 · 실행 중 적용 상태를 대조한다. 파일에 값을 썼다는 사실만으로 실행 환경에 적용됐다고 보지 않는다. 이미 노출된 자격 정보는 코드 삭제와 별개로 회전 · 폐기 상태를 확인한다.

| 종류 | 예 | 있으면 |
|---|---|---|
| 비밀값 | 비밀번호, API 키, 토큰, 연결 문자열의 password, 개인 키 블록, OAuth client secret, 웹훅 서명 키 | 결함. 값이 유효하든 폐기됐든 이력에 남는다 |
| 암호 재료 | 비밀 키 · 난수 seed의 리터럴, 모드가 요구하는 유일성 · 무작위성을 깨는 고정 IV · nonce · salt | 용도와 알고리즘 요구로 판정한다. GCM의 같은 키 · IV 재사용과 비밀번호별 salt 미분리를 확인한다. 공개 상수 · 시험 벡터와 비밀 키를 구분한다 |
| 계정 | 기본 관리자 계정, 지원용 계정, 시험 계정이 운영 빌드에 | 결함. "디버그 전용" 이어도 빌드에 들어가면 같다 |
| 환경값 | 서버 호스트 · IP · 포트 · URL, 절대 경로, 테넌트 ID, 공유 폴더, 라이선스 서버 | 위험. 교체 · 회전이 불가능하고 내부 구조가 노출된다. 정본 설정과 실제 쓰임을 대조한다 |
| 기능 우회 | `if (user == "admin")`, `DEBUG = True`, 검증을 끄는 상수, 특정 IP 허용 | 결함 |

허용하는 것(근거를 적을 때만): 문서로 공개임을 확인한 식별자(OAuth client id, 공개 키, 앱 ID), 시험 경로에만 있고 운영에서 쓸 수 없음이 확인된 시험 자격, 운영 빌드에서 쓰이면 실패하는 로컬 개발 기본값, 키 이름과 파일 경로(값은 아니다).

## 빌드 때 박히는 값

- 클라이언트 번들의 `VITE_*` · `NEXT_PUBLIC_*` · `REACT_APP_*` 는 공개다. 브라우저 번들에는 비밀값이 있을 수 없고 공개 식별자만 둔다.
- Rust `env!()` · `include_str!()` 는 빌드 머신의 값을 바이너리에 박는다. 런타임 값은 `std::env::var` 나 설정 파일로 읽는다.
- Tauri · Electron 의 리소스, 모바일 assets, Dart `--dart-define` 도 설치판에 그대로 남는다. 앱 안에 비밀값이 필요하면 서버가 대신 호출한다.
- git 이력에 한 번이라도 커밋된 값(`git log -p -S'<값>'`)은 지금 없어도 회전한다.
- 일반 텍스트 검색이 놓치는 값을 직접 본다: 문자열 결합 · 인코딩으로 조립한 값, 여러 줄 YAML 값, Dockerfile 의 `ENV KEY value`, 자원 파일(`.resx`, `strings.xml`), 번들, 바이너리 문자열.

통과 근거는 셋이다: 검색 결과와 각 건의 판정, 직접 본 자리의 목록, 비밀값의 실제 출처(설정 파일 이름 · 환경변수 이름 · 저장소 종류). 셋을 모두 갖췄을 때만 통과를 준다. 판정 문서 · 로그 · 보고에는 비밀값(시험 픽스처 · 예제의 것도)과 개인 사용자 프로필 경로를 파일:줄 · 필드 이름 · `<사용자>` 자리표시로 적는다.

## 인증 횟수 제한

로그인 · OTP · 비밀번호 재설정의 시도 횟수를 세는 값이 어디에 있는지 적는다: 서버 측 저장소인가, 요청마다 새로 0이 되는 메모리인가. 상한과 넘었을 때 동작(잠금 · 지연 · 추가 인증)과 실패 로그를 함께 적는다. 클라이언트에서만 세는 횟수는 없는 것과 같다.
