# 보안 판정과 작업 중 자료 보호

## 판정

| 판정 | 영문 | 의미 |
|---|---|---|
| 통과 | `PASS` | 고른 경계의 통제와 실제 도달 경로를 근거로 확인 |
| 결함 | `FAIL` | 재현 가능한 약점이나 필요한 통제의 부재 확인 |
| 위험 | `RISK` | 성공 공격은 미확정이지만 의미 있는 설계 · 설정 위험의 근거 존재 |
| 해당 없음 | `N/A` | 현재 범위에 이 경계가 걸리지 않음을 확인 |
| 확인 못 함 | `NOT VERIFIED` | 자료 · 환경 · 권한 부족으로 중요한 경계를 확인하지 못함 |

- 공격 경로가 막혀 있으면 막은 것이 무엇인지 본다. 그 경로를 막으려고 둔 통제(검사 · 권한 · 설정)이고 코드 · 설정 · 결정 기록에서 그 의도가 확인되면 통과로 둔다. 다른 목적의 코드가 우연히 막고 있으면 결함으로 두고 심각도에 실제 조건을 반영한다.
- 프로젝트의 실제 계약 · 위협 모델 없이 횟수 제한 · 세션 수명 · 암호값을 임의로 정하지 않는다.
- 공공기관 · 감리용 통제 목록은 그 일을 맡았을 때만 쓰고 모든 일에 붙이지 않는다.

## 가림과 내보내기

민감한 내용을 가렸다면 본문뿐 아니라 숨긴 열 · 메타데이터 · 주석 · 첨부 · 이전 판 · 썸네일 · 수식 · 로그 · 오류 메시지까지 실제 출력과 배포 파일에서 확인한다. 지운 파일 이름이나 겉보기 검은 상자만으로 익명화 · 복구 불가를 주장하지 않는다.

## 작업 중 파일과 자격

필요하지 않은 `.env` · 키 · 인증서 · 토큰 파일은 열지 않고, 필요하면 해당 항목만 읽는다. 시험 · 예시 · 전달물에는 실제 고객 식별자 · 계정 · 개인 경로 대신 가짜 값을 쓴다. 자격이 부족해 막히면 다른 키를 찾아 우회하거나 권한을 넓히지 않고 필요한 권한을 알린다.
