# 디자인

먼저 묻는다: "기존 틀로 할까요, 새로 만들까요?" 틀 목록이 비어 있으면 새로 만들기로 간다.

## 1. 기존 틀 쓰기

1. 틀 목록을 번호·이름·한 줄 설명·견본 그림으로 보인다. 쓰임 갈래가 이번 매체와 맞는 것만 보인다.
2. 주제에 맞는 추천 하나를 까닭과 함께 표시한다.
3. 사용자가 고르면 내용(대본, 화면 문구, 숫자, 사진)을 받는다. 내용이 없으면 요청서로 초안을 써서 확인받는다.
4. 고른 틀의 DESIGN.md 를 작업으로 복사하고, 그 틀에 내용을 넣은 시안 2~3개를 만든다. 시안은 같은 틀에서 구성만 다르게 한다(첫 장면 여는 방식, 장면·장 수, 강조할 곳).
5. 사용자가 하나를 고르면 그 구성으로 구성표를 쓴다.

완료: 작업 안에 고른 틀의 DESIGN.md 가 있고 시안 하나가 골라졌다.

## 2. 새로 만들기

1. 아래 질문지를 한 번에 넷까지 묶어 묻는다. 분위기부터 묻고, 분위기 답에 맞춰 뒤 질문의 추천을 바꾼다. 요청서에서 답한 칸은 건너뛴다.
2. 묶음이 끝날 때마다 DESIGN.md 의 그 칸을 채운다. 사용자가 묻지 않은 칸은 답에서 계산해 추천으로 채운다.
3. 다 채우면 DESIGN.md 전체와 그 값을 입힌 대표 그림 한 장을 보인다. 움직임이 있는 매체면 속도·멈춤·전환이 보이는 3~5초 견본을 더한다.
4. 고칠 곳을 받아 그 칸만 바꾸고 대표 그림과 견본을 다시 보인다.

완료: DESIGN.md 의 값이 모두 차 있고, 사용자가 대표 그림(과 견본)을 승인했다.

## 3. 디자인 질문지

보기에 "(추천)"을 붙여 보인다. 추천은 분위기·쓰는 곳에 맞춰 바꾼다.

### 공통 칸

| 칸 | 묻는 말 | 보기 예 | AI가 정하는 것 |
|---|---|---|---|
| 분위기 | 전체 느낌은? | 차분 / 경쾌 / 고급 / 유쾌 / 추천해줘 | `description`, 뒤 질문의 추천 |
| colors | 바탕은 밝게, 어둡게? 주인공 색은? 강조 색은? | 어두운 바탕 / 밝은 바탕 / 회사 색, 참고 그림에서 뽑기 | 보조 색, 선 색, 글자 색, 대비 검사 |
| typography | 글자 느낌은? 제목 크기는? 한 화면 글자 양은? | 굵은 고딕 / 단정한 고딕 / 명조, 큰 글자 한 줄 / 두세 줄 | 단계별 크기·굵기·줄 간격, 최소 크기, 대체 글꼴 |
| spacing | 화면을 얼마나 채울까? | 여백 넉넉히 / 보통 / 꽉 차게 | 기본 단위와 단계 |
| shapes | 모서리는? 선 굵기는? 주인공 도형은? | 각지게 / 살짝 둥글게, 가늘게 / 보통 / 굵게 | 크기 단계 |
| components | 아이콘은? 단계 번호는? 끝 화면은? | 선 아이콘 / 채운 아이콘 / 없음 | 부품마다 쓰는 값 이름 |
| 크기 변형 | 다른 화면비·크기로도 쓰나요? | 없음 / 세로판 / 인쇄판 | 크기별 배치·글자 크기 차이 |
| 하지 말 것 | 이것만은 싫다는 것? (여러 개) | 그림자·빛 번짐 / 화려한 전환 / 글자 많음 / 빠른 깜빡임 | "하기" 목록 |

### 영상 칸

| 칸 | 묻는 말 | 보기 예 | AI가 정하는 것 |
|---|---|---|---|
| format | 화면 비율·초당 장 수(`fps`, 기본 30)·길이는? 가로·세로 둘 다면 세로판 길이는? | 세로 / 가로 / 둘 다, 30장 / 60장 / 24장 | 해상도, 안전 구역(앱 버튼·자막 자리) |
| motion | 빠르기는? (길이는 30fps 기준 프레임으로 적는다) 멈출 때 느낌은? 여러 개는 차례로, 한꺼번에? 글자 머무는 시간은? | 0.6초 / 0.4초 / 0.25초, 부드럽게 / 튀며 / 딱 | 길이 단계, 가감속 곡선, 한 번에 움직이는 수, 읽는 시간 계산식 |
| transitions | 장면이 바뀔 때는? 끝 장면으로 갈 때는? | 같은 도형이 이어 움직임 / 밀어내기 / 바로 끊기 / 서서히 | 전환마다 길이 |
| camera | 화면이 움직여도 되나? | 고정 / 천천히 다가가기 / 도형 따라가기 | 다가가는 배율, 따라가는 지연 |
| audio | 배경음악은? 효과음은? 전환을 박자에 맞출까? | 없음 / 잔잔 / 신나게, 도착에만 / 움직임마다 | 전체 소리 크기, 목소리와 음악 차이, 박자 |
| captions | 자막은 영상에 박기, 파일로, 둘 다? 모양은? | 둘 다 / 박기 / 파일만 / 없음, 반투명 띠 / 테두리 글자 | 한 줄 글자 수, 줄 수, 최소 표시 시간, 위치 |

묶음 순서는 분위기·규격 → 색 → 글자 → 여백·도형 → 움직임 → 전환·카메라 → 소리 → 자막 → 부품 → 하지 말 것·크기 변형이다.

### 다른 매체 칸

PPT `slide`(비율, 격자, 제목 자리, 차트 꼴), 문서 `page`(판형, 여백, 머리글·바닥글, 표 꼴), 엑셀 `sheet`(머리행, 숫자 서식, 입력 칸 표시, 조건부 서식), 이미지 `canvas`(크기, 구도, 글자 자리). 채우는 법은 같은 꼴이다: 칸마다 묻는 말과 보기, 추천, AI가 정하는 것을 두고 한 번에 넷까지 묶어 묻는다.

## 4. DESIGN.md 쓰기

빈 틀은 [DESIGN.md](../templates/DESIGN.md). 맨 위 YAML 에 값을 두고, 아래 글에 칸마다 하는 일과 까닭, 하지 말 것, 크기 변형, 다루지 않는 것을 쓴다. 값은 중괄호 경로로 서로 가리킨다(`{colors.surface}`, `{motion.duration.short}`, `{transitions.default}`). 영상 칸의 키는 빈 틀의 키 이름을 그대로 쓰고, `fps` 는 값 칸(기본 30), 움직임 길이는 30fps 기준 프레임으로 적는다. 빈 틀의 영상 칸에 적힌 값은 영상 기본값이다. 질문지에서 따로 정하지 않은 칸은 그 값을 그대로 둔다. 구성표도 이 이름을 쓰므로 값 하나를 바꾸면 그 이름을 쓴 곳이 모두 함께 바뀐다.
