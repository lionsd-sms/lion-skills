# 환경 점검과 도구 추천

이번 일에 필요한 기능만 본다. 판단할 근거가 모이면 점검을 멈추고 남은 확인은 기록에 적는다.

## 1. 기능 뽑기

요청서의 답을 관찰할 수 있는 기능 단위로 바꾼다.

| 요청서의 답 | 뽑는 기능 예 |
|---|---|
| 도형이 이어서 움직이는 설명 영상 | 개체 위치·크기를 시간축에서 제어, 한글 글꼴, 영상 출력 |
| 본인 목소리 내레이션 | 음성 녹음 또는 음성 복제, 길이에 맞춘 자막 |
| 실사 같은 제품 장면 | 참조 사진 기반 영상 생성, 생성 결과 받아오기 |
| 다음 달에 숫자만 바꿔 다시 씀 | 자료와 디자인을 나눈 원본, 다시 출력 |
| 편집 가능한 PPT | 슬라이드 개체를 텍스트·도형으로 유지, 실제 크기 렌더 |
| 여러 사람이 입력하는 엑셀 | 입력 칸 제한, 수식 재계산 |

## 2. 수단 확인

기능마다 쓸 수단을 찾고 아래 넷을 따로 확인한다. 앞 단계가 되었다고 뒤 단계를 된 것으로 적지 않는다.

| 확인 | 묻는 것 |
|---|---|
| 설치 | 프로그램·패키지·글꼴·모델이 있는가, 판은 무엇인가 |
| 실행 | 이 세션에서 명령이나 연결로 실제로 돌아가는가 |
| 연결 | 계정·라이선스·권한이 준비됐고, AI가 명령·API·스크립트·화면 조작 중 무엇으로 다루는가 |
| 출력 시험 | 5절 작은 시험으로 확인한다 |

실행 장소(이 PC, 원격 서버, 컨테이너, 브라우저 서비스)를 나눠 적는다. 한 장소에서 얻은 결과를 다른 장소의 결과로 옮겨 적지 않는다. 찾지 못한 프로그램은 "이 세션에서 찾지 못함"으로 적는다.

## 3. 상태 넷

| 상태 | 뜻 | 다음 행동 |
|---|---|---|
| 있고 시험함 | 출력 시험까지 통과 | 그대로 쓴다 |
| 있지만 시험 안 함 | 설치나 실행만 확인 | 작은 시험을 돌린다 |
| 없지만 대안 있음 | 다른 수단이나 사용자 손 작업으로 가능 | 대안과 품질 차이를 알린다 |
| 없음 | 이 환경에서 할 수단이 없음 | 후보를 조사해 추천한다 |

## 4. 후보 비교와 추천

없는 기능은 후보 2~3개를 공식 자료(제작사 문서, 가격표, 내려받기 쪽)로 조사해 표로 비교하고 하나 추천한다.

| 비교 칸 | 적는 것 |
|---|---|
| 비용 | 무료 / 유료(월·건당 금액) / 무료 한도 |
| 설치 크기 | 내려받을 크기와 설치 뒤 크기 |
| 품질 | 이번 기능에서 기대할 결과, 알려진 한계 |
| AI 조작 | 명령·API·스크립트로 AI가 직접 다루는지, 사람이 화면에서 해야 하는지 |
| 자료 전송 | 외부 서버로 나가는 자료 |

도구는 능력으로 묶어 고른다. 예: 코드로 움직임을 짜는 렌더러(정확한 문구와 반복 수정에 맞음), 타임라인 편집기(사람이 손으로 다듬기 좋음), 생성형 영상 서비스(실사 장면에 맞고 결과가 매번 달라짐). 사람 손 작업이 필요한 수단이면 넣을 문구·참조 파일·설정·돌려받을 파일 규격까지 준비해 건넨다.

설치·다운로드·결제·계정 연결은 크기·비용·자료 전송 범위를 알리고 승인받은 뒤 한다.

## 5. 작은 시험

고른 수단으로 3~5초 영상, 한 장, 작은 시트처럼 가장 작은 결과를 만들어 연다. 확인할 것은 이번 일의 핵심 기능(한글이 깨지지 않음, 같은 개체가 장면을 건너감, 수식이 다시 계산됨)이다. 정지 그림만 보고 움직임을 확인했다고 적지 않는다.

## 6. 기록과 다시 보기

작업 폴더의 정해진 자리에, 없으면 작업 자료 옆에 기록을 남긴다. 칸: 기능, 수단과 판, 실행 장소, 상태, 근거(직접 확인 / 사용자 말 / 이전 기록 / 공식 자료), 확인한 날, 남은 것.

다음 일은 기록을 먼저 읽고 바뀐 것만 다시 본다.

| 이럴 때 | 다시 볼 것 |
|---|---|
| 같은 결과물의 문구·색만 수정 | 다시 보지 않는다 |
| 새 기능 요청(예: 목소리 추가) | 그 기능에 드는 수단만 |
| 새 프로그램을 설치했다는 말 | 그 프로그램의 판·실행·출력 시험 |
| 실행 오류, 프로그램 업데이트 | 영향을 받은 판정만 |
| 다른 PC·컨테이너로 옮김 | 새 장소로 따로 적는다 |
