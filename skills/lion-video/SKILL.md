# 영상 만들기·고치기

영상을 값(DESIGN.md)과 초·프레임 장면표로 짜서 렌더하고, 렌더한 파일을 시간 구간으로 떠서 움직임까지 확인한다.

## 함께 여는 스킬

이 스킬을 열었으면 파일을 읽거나 고치기 전에, 아래 조건에 맞는 스킬을 Skill 도구로 연다(Codex 는 그 스킬의 SKILL.md 를 읽는다). 이미 열려 있으면 건너뛴다.

- 작업 폴더에 DESIGN.md·구성표(장면표)가 없어 빈 틀이 필요할 때: `lion-production`
- 기존 영상·소리 파일을 자르거나 고칠 때: `lion-file-work`

## 작은 수정

- 문구·시각만 바꿀 때: 장면표의 그 칸만 고쳐 다시 렌더하고, 고친 구간과 앞뒤 전환을 다시 떠서 본다. 글자 수가 늘면 머무는 시간이 장면 안에 드는지 셈한다.
- 색·글자·속도를 바꿀 때: DESIGN.md 값을 고쳐 전체에 반영하고 장면마다 정지 그림을 다시 뜬다.
- 자막만 넣을 때: 대본이 있으면 대본 글자로 자막을 만들고 박을지 파일(SRT)로 줄지 올릴 곳에 맞춘다.
- 몇 번째 수정에 무엇을 바꿨는지 장면표 아래 수정 기록에 한 줄 적는다.

## 새 영상

1. 입력: 작업 폴더의 요청서·DESIGN.md·장면표(구성표)·대본을 먼저 읽는다. 작업 폴더에 영상 도구(틀 목록, 렌더·합치기·자막 명령)가 있으면 그 안내와 명령을 따르고, 사용자의 제작 기준 문서가 있으면 함께 읽고 따른다. 빈 것만 짧게 묻는다: 무엇을 누구에게, 올릴 곳과 화면비, 길이, 문구·대본, 목소리·자막. 모르면 추천값으로 채우고 알린다.
   완료: 다섯 항목이 답이나 추천값으로 정해졌다.
2. 수단: 장면마다 제작 방식을 고르고, 쓸 수단마다 이 PC에서 3초 안팎의 짧은 출력 시험을 돌린다. 설치·결제·계정 연결은 승인 뒤에 한다.
   완료: 쓸 수단마다 시험 파일이 열리고 재생된다.
3. 값과 장면표: 작업 폴더의 DESIGN.md·구성표(장면표)를 쓰고, 없으면 그 자리에서 빈 틀대로 만든다. DESIGN.md에 색·글자·움직임·전환·소리·자막 값을 이름으로 적는다. 정해진 값이 없으면 쓰는 곳과 분위기에 맞는 팔레트(바탕·주색·강조 셋)와 글꼴 하나를 추천해 알리고 진행하며, 움직임·전환·소리·자막은 빈 틀 영상 칸의 기본값을 둔다. 장면표에는 장면(SC-001)마다 프레임(초), 화면 문구(TXT-001), 개체(OBJ-A, 이어받음 → 넘김), 움직임(`{motion.duration.short}` 같은 값 경로), 전환, 수단, 소리·자막을 적는다. 같은 개체를 다음 장면까지 들고 가서 상태만 바꾼다. 사용자에게 보여 확인받는다.
   완료: 모든 프레임이 장면 하나에 속하고(장면 사이 빈 시간 0), 장면마다 이어받는 개체와 넘기는 개체가 적혀 있다.
4. 만들기: 장면표의 문구·시각·값 이름을 그대로 옮긴다. 목소리 길이가 나오면 장면표 시각을 다시 맞춘다.
   완료: 장면표의 모든 문구 ID가 렌더본에 들어갔다.
5. 렌더와 검사: 파일 규격(길이, 크기, fps, 소리 트랙)을 재고, 장면별 정지 그림과 전환 구간을 떠서(간격은 이동 길이의 1/5 이하: 12f 이동은 2~3f, 18f 전환은 3f. 0.1~0.2초 간격은 전환 앞뒤 여유 구간에만) 개체가 사라졌다 나타나지 않고 이동하는지, 글자 잘림·겹침·안전 구역·자막 띠·깜빡임을 본다.
   완료: 전환마다 뜬 그림 묶음에서 이어받는 개체가 끊김 없이 보이고, 발견한 문제를 고쳐 다시 떴다.
   "정지 그림이 괜찮다" → 움직임과 전환은 시간 구간을 떠야 보인다.
   "렌더가 끝났다" → 파일이 생겼다는 뜻이다. 화면은 뜬 그림으로 본다.
   소리는 AI가 들을 수 없다. 음량(LUFS·최고점), 줄마다 길이, 무음 구간, 시작 시각을 재어 장면표와 맞대고, 발음·억양·음악과의 어울림처럼 들어야 아는 것은 구간 시각을 짚어 사용자에게 듣고 확인받는다.
6. 전달: 쓴 그림·소리·음악의 출처를 한 줄씩 적는다. 올리기는 비공개로, 사용자 확인 뒤에 한다.
   완료: 소재 줄마다 출처 칸이 차 있고, 올렸다면 공개 범위가 비공개로 확인됐다.
