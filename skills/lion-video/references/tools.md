# 수단과 환경

## 장면 성격으로 제작 방식 고르기

한 영상에 여러 방식이 섞일 수 있다. 장면마다 고르고 장면표의 그 장면 칸에 적는다.

| 장면 성격 | 제작 방식 | 예시 |
|---|---|---|
| 정확한 글자, 도형, 도식, 같은 개체의 연속 움직임 | 코드로 움직임을 짜는 렌더러 (프레임 번호마다 위치·크기·색을 계산) | Remotion, HyperFrames |
| 정교한 합성, 키프레임과 속도 곡선을 손으로 다듬기 | 레이어 편집기 | After Effects |
| 밈·반응·자막 중심, 빠른 컷과 음악 박자 | 컷 편집기 | CapCut, DaVinci Resolve |
| 실사 인물·제품·풍경, 카메라 움직임 | 생성형 영상 서비스 + 편집기 | Runway, Higgsfield |
| 합치기, 자르기, 자막 박기, 규격 재기 | 명령줄 영상 도구 | ffmpeg, ffprobe |

- 문구를 자주 바꾸거나 같은 디자인을 다시 쓸 영상은 코드 렌더러를 먼저 본다. 값과 문구를 고쳐 다시 렌더하면 끝난다.
- 생성형 장면은 길이·규격·다음 장면과의 연결을 따로 검사한다. 정확한 한글 글자는 생성 장면 위에 렌더러나 편집기로 얹는다.
- 작업 폴더에 영상 도구(틀 목록, 렌더·합치기·자막 명령)가 있으면 그 틀과 명령을 먼저 쓴다.

## 이 PC에서 확인하기

깔려 있다는 것만으로 쓸 수 있다고 보지 않는다. 쓸 수단마다 아래를 확인하고 결과를 작업 기록에 한 줄씩 남긴다.

| 확인 | 질문 |
|---|---|
| 있음 | 실행 파일·프로젝트 의존성의 경로와 버전이 나오는가 |
| 기능 | 이번 영상에 필요한 기능(연속 이동, 한글 글꼴, 세로 해상도, 소리 트랙)을 하는가 |
| 조작 | AI가 명령·API·스크립트로 조작할 수 있는가. 화면 조작만 되면 사용자 손 단계를 넣은 안과 다른 수단을 견준다 |
| 자원 | 글꼴, 메모리, 그래픽 메모리, 모델 파일, 저장 공간이 있는가 |
| 승인 | 설치, 결제, 계정 연결, 외부로 자료 보내기가 허락된 범위인가 |
| 출력 | 같은 개체가 이어 움직이는 3초 안팎 시험 영상이 실제로 나오고 재생되는가 |

- 시험 영상은 렌더와 검사의 규격 재기와 구간 뜨기로 확인한다.
- 같은 영상의 문구·색 수정은 앞의 확인을 다시 쓴다. 목소리·실사처럼 새 기능이 붙거나 수단이 바뀌면 그 부분만 다시 확인한다.

## 모자랄 때

사용자에게 다섯 가지를 한 번에 보인다.

1. 어떤 기능 때문에 필요한가
2. 지금 있는 수단으로 하는 방법
3. 더 깔거나 연결하면 달라지는 것
4. 비용, 내려받을 크기, 밖으로 나가는 자료
5. 깔고 나서 무엇으로 확인할 것인가

설치·결제·계정 연결은 사용자가 승인한 뒤에 한다.

## 돌릴 때

- 도구가 한글·공백 경로에서 실패하면 영문 임시 폴더에서 돌리고 결과만 옮긴다.
- 도구의 사용 통계 보내기는 끄는 설정이 있으면 끈다.
- 도구가 작업 폴더 밖에 쓰는 동작은 먼저 알리고 승인받는다.
