# 운영 빌드 · Windows 설정

## 운영 빌드에 남는 것

- 운영 빌드가 소스맵을 내보내지 않는지(번들러의 sourcemap 이 true · inline 이 아님), 설치판 · 배포 폴더에 `.map` 파일이 실리지 않는지 본다. 오류 추적에 소스맵이 필요하면 hidden 으로 만들어 설치판 · 배포 폴더 밖에 둔다.
- 남은 디버그 코드(`debugger;`, `breakpoint()`, `Debugger.Break()`, `dbg!`, `DEBUG = True`, `devtools: true`, 디버그용 우회 계정 · 분기)는 운영 빌드 설정(`Release` 구성, `NODE_ENV=production`, `--release`)에서 실제로 빠지는지로 판정한다.

## Windows 서버 · PC 설정 변경

계정 · 서비스 · 레지스트리 보안값 · 방화벽 · 원격 접속 · 로그 정책 · 공유 · 패치를 바꾸는 코드나 장비 준비 작업에 쓴다.

1. 대상 OS 판 · 에디션 · 장비 역할을 확인한다. 현장별 역할이 다르면 실행 때 역할과 설정을 구분해 기록한다.
2. 바꿀 키 · 값의 실제 이름 · 타입 · 지원 여부 · 정책 우선순위를 확인한다. 없는 키나 지원이 끝난 설정을 추정해 만들지 않는다. 레지스트리 값을 다시 읽은 것과 운영체제가 그 값을 적용한 것은 따로 확인한다.
3. 서비스 이름이 목록에 있다는 이유만으로 중지하지 않고 실제 의존성을 대조한다. 공유는 경로 · 주체 · 허용 동작을, 원격 접근은 접속 범위 · 인증 · 잠금 · 감사 경로를 함께 본다.
4. 바꾸기 전 값 · 적용 대상 · 되돌릴 명령을 먼저 확보한다. 쓴 뒤 서비스 상태 · 실제 공유 · 방화벽 프로필 · 정책 적용 결과 · 필요한 재부팅을 확인한다. 쓰기 명령 성공만으로 끝내지 않는다.
5. 방화벽 · 백신 · 업데이트 · 인증 같은 보호를 약하게 하는 선택은 기존 승인 정책과 대체 조치를 확인하고, 정책이 미정이면 영향을 보이고 그 변경만 결정을 기다린다.
6. 결과에 적용 전후 · 장비 역할 · 실패와 부분 적용 · 복구 결과를 남긴다. 확인할 수 없는 역할 · 적용 효과는 미확인으로 남긴다.
