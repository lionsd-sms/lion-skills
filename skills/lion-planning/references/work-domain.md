# 업무 판단

낯선 업무를 기획할 때 분야 이름과 결과물 형식을 따로 본다. 화면·파일·보고서의 틀과 그 안의 업무 내용은 각각 확인한다.

## 실제 업무에서 시작

```
분야 → 하위 업무 → 실제 역할 → 판단과 행동 → 입력 → 결과 → 틀렸을 때 영향
```

같은 분야여도 하위 업무마다 책임과 규칙이 다르다(판매·디자인·생산 관리, 장부·결제·성과 분석). 지금 쓰는 자료·용어·상태·업무 양식과 대표 사례 하나로 어떤 차이가 필요한지 확인한다.

중요한 규칙마다 아래를 완성 모습에 잇는다.

| 확인할 것 | 가를 질문 |
|---|---|
| 개념과 관계 | 무엇을 따로 식별하나, 상태·소유·시간·단위는 어떻게 이어지나 |
| 핵심 규칙 | 어떤 계산·결정·금지 조건이 왜 성립하나 |
| 실무 예외 | 반려·수정·실패·부분 처리·취소 때 누가 무엇을 되돌리나 |
| 좋은 결과 | 담당자가 어디서 받아들이거나 거절하나, 무엇과 대조하나 |
| 현장 제약 | 조직의 정책·권한·계약·물리·제작 조건 가운데 무엇이 걸리나 |

## 빈 곳 채우기

- 사용자가 준 실제 자료와 담당자의 경험을 공개 자료의 요약보다 앞에 둔다.
- 현장만 정할 수 있는 값(세율, 허용오차, 승인 권한, 심사 기준)은 사용자에게 구체적으로 묻는다. 업계 관행으로 채워 확정하지 않는다.
- 부족한 것이 분야 지식인지, 환경 사실인지, 실행 수단인지 가려 그에 맞게 채운다. 확인되지 않은 핵심은 「미확인」으로 현황표에 남기고, 그것에 기대지 않는 일은 계속한다.
- 빈 파일·지식 카드·전문가 역할을 분야마다 미리 만들지 않는다.

## 계획에 넣기

- 중요한 규칙은 결과물의 계산·상태·절차에 들어가게 하고, 정상·예외·경계 사례의 기대 결과를 독립적으로 정해 완료 기준에 넣는다.
- 지금의 절차와 이미 만든 결과의 값은 대조할 자료로 쓰고, 업무 규칙으로 따로 확인한다.
- 실제 표본 하나를 입력부터 받아들임·반려까지 따라가며 빠진 단계를 찾는다.

## 확인의 범위

기술 검사, 결과물의 표현, 업무 규칙, 실제 사람의 사용을 각각 맞는 수단으로 확인하도록 확인 방법을 나눠 적는다. 실물 제작·측정·사람의 전문 검토가 필요한 주장은 그 일을 한 사람과 범위를 적고, 하지 않은 인증·전문 검토는 계획과 보고에 쓰지 않는다.
