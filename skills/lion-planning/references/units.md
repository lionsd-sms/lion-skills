# 단위 자르기

## 기능 묶음이 여럿일 때

요청 하나에 따로 확인할 수 있는 기능 묶음(계정, 결제, 알림)이 여럿 들어 있으면 단위를 쓰기 전에 묶음 표를 만든다.

```
묶음 이름 │ 맡는 일          │ 기대는 묶음
계정      │ 가입·로그인       │ -
결제      │ 요금·청구         │ 계정
알림      │ 메일 보내기       │ 계정
보고      │ 사용량 화면       │ 결제, 알림
만들 순서: 계정 → 결제·알림 → 보고
```

- 기대는 방향은 한쪽으로만 흐른다. 서로 기대는 두 묶음은 하나로 합친다.
- 묶음 이름은 한 번 정하면 끝까지 바꾸지 않는다. 계획 · 파일 · 보고가 같은 이름으로 묶음을 가리킨다.

## 단위 자르기

- 동작 하나의 단위에는 저장·처리·화면이 함께 들어간다(「계정 만들기」).
- 더 나눌 신호:
  - 완료 기준이 세 줄을 넘는다.
  - 단위 이름에 「그리고」가 들어간다.
  - 서로 무관한 영역 둘을 건드린다.
  - 읽을 자료가 에이전트 하나의 대화를 채울 양이다.
- 지금 구조 때문에 바꾸기가 어려우면 동작은 그대로 두고 바꾸기 쉽게 정리하는 단위를 앞에 둔다.
- 공용 이름이나 자료 모양을 한꺼번에 바꾸는 넓은 변경은 동작 하나로 자를 수 없다. 이 순서로 자른다.
  1. 새 꼴을 옛 꼴 옆에 더한다(아무것도 깨지지 않는다).
  2. 쓰는 곳을 묶음별(폴더, 모듈)로 옮긴다. 묶음마다 단위 하나이고, 끝날 때마다 돌아가는 상태다.
  3. 쓰는 곳이 없어진 옛 꼴을 지운다.
- 자료 전환 단위에는 되돌리는 전환을 짝으로 두고 둘 다 확인한다.

## 순서와 병렬

- 결과가 불확실하거나 실패하면 계획 전체가 바뀌는 단위를 앞에 둔다.
- 필요한 자료 · 장비 · 도구 · 검증 환경을 실제로 구할 수 있는지 계획 전에 확인한다. 확인하지 못한 것은 완료 조건을 단 앞 단위로 둔다.
- 단위 하나가 끝날 때마다 결과는 쓸 수 있는 상태로 남긴다. 그 단위의 확인 방법이 통과한 뒤 다음 단위로 간다.
- 확인이 결과를 증명하는 순서로 놓는다: 실패하는 시험 → 고침, 기준 측정 → 개선, 빼기 → 다시 짜기.
- 쓰는 파일이 겹치지 않고 서로의 결과를 기다리지 않는 단위끼리 함께 돌린다. 함께 돌릴 단위들이 같은 약속(자료 형식, 이름)을 쓰면 약속을 정하는 단위를 앞에 둔다.
