# 완성 모습 잡기

## 착상 다듬기

사용자가 "이런 게 있으면 좋겠어" 수준의 착상을 가져왔을 때, 고를 수 있는 방향 2~3개로 다듬는다. 방향이 이미 정해진 일은 완성 모습 칸 채우기로 바로 간다.

```
착상 → 한 문장으로 다시 쓰기 → 쓰는 사람·성공 모습 확인 → 변형 5~8개
     → 방향 2~3개로 묶기 → 방향마다 가정 점검 → 객관식으로 고르기 → 하지 않을 것
```

1. 착상을 "누가 · 어떤 상황에서 · 무엇을 못 해 곤란한가" 한 문장으로 다시 쓴다.
2. 쓰는 사람과 성공한 모습이 비어 있으면 그것부터 묻는다. 둘이 정해지기 전에는 방향을 내지 않는다.
3. 변형을 5~8개 떠올린다.
4. 비슷한 변형을 묶어 서로 뚜렷이 다른 방향 2~3개로 줄인다. 업무 착상이면 새로 만들지 않는 안(지금 쓰는 엑셀·기존 앱 기능으로 버티기)도 방향 하나로 견준다. 방향마다 적는다.
   - 쓰는 사람이 얻는 것과, 지금은 그 일을 무엇으로 버티고 있나
   - 가장 어려운 부분
   - 틀리면 방향이 무너지는 가정과 그 가정을 확인할 방법
5. 방향을 객관식으로 묻는다. 추천을 첫째에 둔다. 약한 방향은 까닭을 들어 약하다고 말한다.
6. 고른 방향에 「하지 않을 것」 목록을 붙인다. 항목마다 까닭 한 줄.

틀리면 방향이 무너지는 가정은 계획에서 그 가정을 확인하는 단위를 앞에 둔다.

## 목적에 맞게 조이기

- 기능 · 조작 · 선택지마다 쓰는 사람의 중심 일에 어떻게 쓰이는지 한 줄로 댄다. 지금 목표를 끝내는 데 필요한 연결은 완성 범위에 넣는다. 대지 못하는 것과 범위를 넓히는 것(새 역할 · 정책 · 외부 서비스 · 큰 자료 · 운영 결정)은 사용자가 정할 결정 후보로 돌린다.
- 쓰는 사람은 결과를 직접 쓰는 사람이다. 내부 기능 · 공용 코드면 그것을 가져다 쓰는 개발자와 다음에 고칠 사람이다.
- 오류 화면, 저장 뒤 알림, 정렬, 간격처럼 쓰는 사람이 매번 겪는 세부도 완성 모습에 넣는다.
- 바꿀 수 없는 제약(법·계약·장비·기한·예산)과, 목표끼리 부딪힐 때 앞세울 것(예: 속도보다 자료 보존)을 완성 모습에 함께 적는다.

## 앱·기능에서 볼 것

새 앱·기능의 완성 모습은 아래 흐름으로 옮겨 빈 곳을 찾는다.

| 볼 것 | 확인하는 내용 |
|---|---|
| 목적과 사용자 | 누가 어떤 실제 업무를 끝내며 무엇을 받는가 |
| 진입과 입력 | 시작 상태 · 자료 출처 · 입력 검증 · 필수 권한 |
| 처리와 저장 | 상태 전이 · 계산 · 저장 원본 · 중복 · 동시 변경 |
| 결과와 다음 단계 | 저장 후 화면 반영 · 조회 · 수정 · 내보내기 · 재실행 |
| 예외와 복구 | 빈 값 · 실패 · 부분 성공 · 취소 · 재시도 · 자료 보존 |
| 운영 | 설치 · 설정 · 도움말 · 로그 · 업데이트 · 복구 중 필요한 것 |

- 선택을 합친 뒤 권한 · 자료 · 상태 · 비용 · 사용 흐름이 서로 모순되지 않는지 확인한다. 모순되면 영향을 보이고 그 선택만 다시 묻는다.
- 기존 앱이면 흐름마다 지금 상태를 현황표 상태로 대조한다. 「됨」은 실제 화면 · 경로 · 처리 · 저장을 열고, 사용자가 들어가는 길까지 밟아 본 것에만 쓴다.
- 「숨김」 항목은 기존 기능에 들어가는 길과 찾기 쉬움을 고치는 후보로 둔다.
