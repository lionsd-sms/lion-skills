# 모델과 노력

모델은 판단 능력, 노력은 추론 깊이, 작업량은 읽기·나누기 방식으로 다룬다. 읽을 양이 많으면 맡김·나눔·부분 읽기로 줄이고, 판단이 어려우면 모델과 노력을 올린다.

## 보는 것 넷

| 축 | 낮은 쪽 | 높은 쪽 |
|---|---|---|
| 판단 깊이 | 방법이 정해진 수집·분류·변환·대조 | 요구 해석, 설계, 원인 탐색, 상충 조건, 숨은 반례 |
| 읽을 양 | 몇 파일 | 저장소 전체, 긴 로그, 외부 자료 묶음 |
| 확인 쉬움 | 계산·실행·대조로 바로 확인 | 확인 수단이 없거나 사람 판단이 필요 |
| 되돌리기 어려움 | 작업 사본 안의 변경 | 보안, 데이터 삭제·이전, 배포, 여러 프로젝트 공통 |

판단이 깊거나 확인이 어렵거나 되돌리기 어려우면 처음부터 강한 모델을 쓴다. 약한 쪽부터 차례로 시험하지 않는다. 역할 이름(검수·보안·마스터)만으로 가장 강한 모델을 고정하지 않는다.

## 후보

Claude: Agent 호출의 `model` 칸에 별칭을 쓴다.

| 별칭 | 맞는 일 |
|---|---|
| `haiku` | 좁고 확인 쉬운 찾기·추출·분류·정해진 변환 |
| `sonnet` | 기존 방식 안의 구현·문서·자료 정리와 확인 |
| `opus` | 여러 단계의 문맥·도구·판단을 이어 가는 복합 작업 |
| `fable` | 어려운 추론, 상충 조건, 원인 탐색, 긴 일의 핵심 판단 |

Codex: 실제 이름은 `~/.codex/models_cache.json` 의 `slug` 에서 확인한다. 2026-10-19 에 확인한 목록:

| slug | 지원 노력 | 맞는 일 |
|---|---|---|
| `gpt-6-luna` | low~max | 목표·방법이 정해진 수집·분류·변환 |
| `gpt-6-sol`, `gpt-6.1-sol` | low~max, ultra | 해석·계획·제작·도구·검증을 잇는 일반 복합 작업 |
| `gpt-6-astra` | low~max, ultra | 상충 정책, 여러 원인 가설, 확인이 어려운 핵심 판단 |

다른 환경에서는 그 환경이 실제로 제공하는 목록에서 같은 기준으로 고른다.

## 노력

| 값 | 맞는 일 |
|---|---|
| `low` | 방법·입력·완료 기준이 정해진 짧은 판단 |
| `medium` | 몇 가지 선택을 잇는 제작·확인 |
| `high` | 원인 가설·대안·영향 비교 |
| `xhigh`, `max` | 반례와 수용 기준이 있는 구체적 난점 |
| `ultra` | Codex 에서 그 모델이 지원할 때만. 가장 깊은 추론 |

강한 모델에 낮은 노력도 후보로 본다. 같은 노력 값이라도 모델마다 능력과 비용이 다르다.

## 출발점과 한 단씩 옮기기

출발점은 고를 때 참고하는 자리다. 몫마다 보는 것 넷으로 옮긴다.

| 일의 결 | Claude 출발점 | Codex 출발점 |
|---|---|---|
| 방법이 정해진 수집·분류·변환·대조 | `haiku` · `low` | `gpt-6-luna` · `low` |
| 기존 방식 안의 구현·문서·정리 | `sonnet` · `medium` | `gpt-6-sol` · `medium` |
| 요구 해석·설계·원인 탐색 | `opus` · `high` | `gpt-6-sol` · `high` |
| 상충 조건·숨은 반례·되돌리기 어려운 핵심 판단 | `fable` · `high` | `gpt-6-astra` · `high` |

- 노력 단계는 `low` < `medium` < `high` < `xhigh` < `max`(Codex 는 지원 모델에서 그 위 `ultra`).
- 같은 결 안에서 이번 몫이 가장 어렵고 미묘하면 노력을 한 단 올린다. 판단이 이미 정해져 옮기기만 하면 한 단, 틀이 같은 반복이면 두 단 내린다. 모델은 판단 능력이 모자랄 때만 바꾼다.
- 사용자가 비용·속도 기준을 말하면 모든 출발 노력을 함께 옮긴다: "아껴", "빨리"면 한 단 내리고, "제대로", "넉넉히"면 한 단 올린다. 그 모델에 없는 수준이면 같은 모델에서 가장 가까운 아래 수준을 쓴다.
- 겨루기·두 번째 의견처럼 서로 다른 모델이 필요한 자리는 노력만 옮기고 모델은 바꾸지 않아 서로 다름을 지킨다.

## 넘기는 법

- Claude Code: Agent 호출의 `model`(별칭 또는 전체 ID)과 `effort` 칸에 넣는다. 호출 값이 역할 파일 frontmatter 보다 우선한다. 두 곳 모두 비면 환경 변수 `CLAUDE_CODE_SUBAGENT_MODEL`, 그것도 없으면 주 대화의 모델로 돈다.
- Codex 하위 에이전트: 에이전트를 만들 때 모델 이름과 추론 노력을 함께 적는다. 값은 생성 시 지정 → `config.toml` 의 `[agents]` `default_subagent_model` · `default_subagent_reasoning_effort` → 부모 값 순으로 정해진다. 역할 파일에 `model` · `model_reasoning_effort` 가 있으면 그 값이 생성 시 지정을 이기므로 역할 파일에는 두 키를 쓰지 않는다. 모델만 정하면 그 모델의 기본 노력으로 돈다.
- `codex exec`: `-m <slug> -c model_reasoning_effort="<값>"`.
- `claude -p`: `--model <별칭> --effort <값>`.

사용자가 정한 모델·비용 조건을 지킨다. 영구 기본 모델과 사용자 설정 파일은 바꾸지 않는다.

## 기록과 되짚기

지시서나 진행 기록에 고른 모델 · 노력 · 까닭을 한 줄로 남긴다. 예: `sonnet · medium · 정해진 형식 변환, 시험으로 바로 확인`.

결과가 모자라면 자료·전제·도구·권한을 먼저 본다. 추론이 얕았으면 노력을, 판단 능력이 모자랐으면 모델을 올린다. 같은 종류의 일에 값이 넘쳤으면 다음에는 낮춘다. 호출이 모델 이름을 거부하면 이름을 바꿔 가며 잇달아 시도하지 않는다. 후보 표에서 같은 기준으로 다른 모델 하나를 골라 까닭을 남기고 계속한다. 에이전트 생성이 동시 실행 한도로 거절되면 모델 거절로 보지 않고, 도는 실행 하나가 끝난 뒤 같은 값으로 다시 보낸다. 정해지지 않은 사용자 정책은 올림으로 보낸다.
