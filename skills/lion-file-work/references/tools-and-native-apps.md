# 도구와 원본 앱

## 도구 지원 판정

- 읽기 지원과 편집·렌더링 지원은 따로 확인한다.
- 처음 쓰거나 지원이 불확실한 도구는 작은 실제 입력의 읽기·처리·다시 열기로 시험한다. 명령이나 라이브러리를 발견한 것과 작업 성공은 구분한다. 이미 확인한 같은 기능은 재사용하고, 확인한 기능만 약속한다.
- 필요한 기능마다 `실행 확인`, `발견·미검증`, `추가 의존성 필요`, `현재 사용 불가` 중 하나로 판정한다. 생성·편집·분석·변환·디자인·자동화·검증을 따로 판정한다.
- 실패한 도구는 원인·대체 가능성·보존 손실을 확인한 뒤 바꾼다. 대체가 핵심 결과를 바꾸면 그 선택만 사용자에게 묻는다.
- 클라우드 문서는 실제 연결·권한·편집 API를 확인한다. 로컬 파일 제작과 클라우드 저장은 다른 일이다.
- 도구를 더 설치해야 하면 공식 배포처·판본·공개 검증값(해시)을 확인하고 작업 전용 위치에 설치한다. 검증값이 없으면 그 한계를 기록한다.
- 관리 런타임·전역 PATH·전역 설정·관리되는 의존성 폴더는 그대로 둔다.

## Windows 원본 앱 자동화(COM)

앱이 설치돼 있다는 것은 자동화·저장·다시 열기 성공의 증거가 아니다.

- 실제 실행 파일과 COM ProgID 등록을 확인한다. PATH 탐색 결과는 앱 설치 여부의 근거가 아니다.
- 32비트와 64비트 레지스트리 보기를 따로 본다. 한 보기에 CLSID만 있고 서버 경로가 없으면 다른 비트 보기를 확인한다.
- 쓸 호스트·서버의 비트·판본·라이선스·지원 필터는 작은 실제 문서로 확인한다. 다른 운영체제에서는 그 환경의 지원 API를 쓴다.
- 시작 전 기존 프로세스와 열린 문서를 확인한다. COM 생성 호출은 기존 인스턴스에 붙기도 한다.
- 공유 인스턴스에서는 이번 작업 문서만 열고 닫는다. 앱 종료·설정 변경은 이번 작업이 띄운 인스턴스에서만 하고, 사용자의 열린 문서는 그대로 둔다.
- 새로 띄운 인스턴스는 실제 창 소유 PID·프로세스 시작 시각·문서 경로를 기록하고, 닫을 때 같은 소유인지 다시 확인한다. 문서 이름이나 빈 문서인지는 소유 근거가 아니다.
- 입력은 사본이나 읽기 전용으로 열고 결과는 새 경로에 저장한다. 자동 복구·최근 파일·전역 보안 설정은 그대로 둔다.
- 매크로 보존과 매크로 실행 검증은 따로 확인한다.
- 단계마다 시작·성공·오류를 기록하고 제한 시간을 둔다. 멈출 수 있는 COM 호출은 별도 프로세스의 감시로 시간 제한을 건다. 같은 프로세스의 타이머는 멈춘 호출을 끊지 못한다.
- 호출이 멈추면 문서·대화상자·인수 바인딩·권한 중 원인을 가린다. 다른 지원 호출 경로는 작은 입력으로 시험한 뒤 쓴다. 멈춤은 미설치의 증거가 아니다. 재시도에는 횟수 상한을 둔다.
- 남은 인스턴스 정리는 소유가 입증된 것만 한다.
- 저장 뒤 최종 파일을 다시 열어 내용·기본 개체 편집성·실제 쪽을 확인한다. 앱 한 판본에서의 성공은 그 판본·그 문서에 대한 결과다.
