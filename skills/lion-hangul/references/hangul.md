# HWP와 HWPX

## 형식과 경로

- HWP 바이너리와 HWPX ZIP/XML을 구분한다. HWPX 패키지 읽기·텍스트 추출은 생성·서식 편집·한글 호환과 별개다.
- 필요한 기능은 응용프로그램·지원 API·라이브러리·변환기로 실제 확인한다. 없으면 분석과 원본 보존까지 하고 제한을 보고한다.
- HWP의 압축·배포용·암호·버전은 공식 명세와 파서 지원으로 확인한다. 일반 HWP는 HWP 파서로 연다. python-docx와 ZIP 도구는 HWP를 열지 못한다.

## HWPX 읽기와 편집

1. `mimetype`·`Contents/content.hpf`·`Contents/header.xml`·구역 XML·`META-INF`·`BinData`의 실제 구조를 확인한다. ZIP 목록·해시·XML 검사는 HWPX 명세 검증과 구분한다.
2. 읽기 순서는 `content.hpf`의 spine으로 정한다. 파일명 순서는 구역 순서의 근거가 아니다.
3. 문단·run·텍스트·표·개체와 header의 서식 참조를 함께 해석한다. `hp:t`만 이어 붙인 결과는 표 배치·필드·서식의 복원이 아니다.
4. 범위 밖의 서식 ID·자원·구역·메타데이터는 그대로 두고, 스크립트는 실행 없이 그대로 보존한다.
5. 명세·참조 검사와 실제 호환 응용프로그램의 열기·렌더링으로 검증한다. 미리보기가 본문 변경을 반영하는지도 확인한다.

호환 응용프로그램이 없으면 결과를 새 파일로만 내고 원본은 그대로 둔다. 대체 출력은 목적과 변환 손실을 확인한다.

## 한글 프로그램 자동화

- desktop COM 매뉴얼과 그 판본에 설치된 필터를 확인한다. 웹 HwpCtrl의 같은 이름 API는 desktop 지원 근거가 아니다.
- HWP·HWPX·PDF 저장 뒤 다시 열기·본문·표·미리보기·출력을 대조한다. 파일 경로 검사와 보안 등록은 그대로 둔다.
