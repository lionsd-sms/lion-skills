# 앱 개발

사용자가 볼 결과와 목적을 먼저 짧게 말한다. 프로젝트 규칙·기존 변경·실제 코드와 실행 상태·이미 받은 결정을 확인하고, 아직 결과를 바꾸는 선택만 추천안과 함께 묻는다. 기존 권위와 사용자 수정을 보존하며 필요한 범위만 고친다. 넓거나 되돌리기 어려운 변경에는 복구 기준점을 만든다. 폴더·문서 자리, 작업 기록, 커밋 꼴은 프로젝트 규칙 문서의 폴더 틀을 따른다.

기능은 입력·상태·출력·실패·복구 경계를 연결해 구현한다. 화면은 실제 화면과 조작, API와 자료는 호출자·저장·호환 경로, 설정은 적용값을 확인한다. 변경한 동작을 독립 기대값과 대조하고, 필수 결과가 미확인이면 완료로 보고하지 않는다. 시험을 통과시키려고 기대값을 낮추거나, 시험을 지우거나 건너뛰거나, 검사를 끄지 않는다.

바꾼 동작이 제품 명세·화면 문서·결정 기록과 달라지면 같은 변경에서 그 문서 줄을 고친다. 명세와 다르게 만들어야 하면 다른 점과 까닭을 보이고 묻고, 답을 받은 뒤 명세 줄을 고친다.

줄이지 않는 것: 신뢰 경계의 입력 검증, 데이터 손실을 막는 오류 처리, 보안, 접근성, 실제 장비 보정, 사용자가 요청한 것.

## 함께 여는 스킬

이 스킬을 열었으면 파일을 읽거나 고치기 전에, 아래 조건에 맞는 스킬을 Skill 도구로 연다(Codex 는 그 스킬의 SKILL.md 를 읽는다). 이미 열려 있으면 건너뛴다.

- 코드를 고치거나 패키지를 더하거나 실행용 bat 파일을 만들 때: `lion-dev-checks`
- 새 앱·새 기능의 완성 모습과 범위를 정해야 할 때: `lion-planning`
- 폴더 자리·프로젝트 틀·표준화가 걸릴 때: `lion-project-rules`
- 화면 문구를 쓰거나 다듬을 때: `lion-writing-polish`
- Tauri 2 앱(`src-tauri/tauri.conf.json` 이 있음)의 앱 명령·권한·웹뷰 설정·플러그인·updater·Windows 설치판을 만들거나 고칠 때: `lion-tauri`
