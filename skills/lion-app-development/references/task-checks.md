# 작업별 확인

## 기능

- 가르는 쟁점: 진입 위치 · 메인 표시 범위 · 화면 형태 · 단계 · 상태 · 실패·취소 · 완료 뒤 반영 · 작은 화면·키보드. 정해지지 않은 쟁점만 추천안과 함께 묻는다.
- 자료 모양과 그것을 묶을 구조(상태 기계·표·타입 모델)를 논리보다 먼저 정한다.
- 구현 중에는 형 검사와 바뀐 곳의 시험 파일을 자주 돌리고 전체 시험은 끝에 한 번 돌린다.
- 공유 부품을 고치면 모든 소비자에 옮기고 각각 확인한다.
- 빈 값·긴 내용·실패·취소·재시도를 실제로 넣어 본다.
- 기능이 실제로 도는 화면에서 확인한다. 결론을 못 낸 확인과 다른 화면에서 한 확인은 통과로 치지 않는다.

## 새 앱

- 기능을 짓기 전에 모든 다음 단계가 쓸 뼈대(공통 타입·시험 장치·검사 명령)를 먼저 만든다.
- 루트·문서·실행 파일 자리는 프로젝트 규칙 문서의 폴더 틀을 따른다.

## 정리·리팩터링

- 구조를 옮기기 전에 특성 시험·스냅숏·옛·새 출력 비교로 지금 동작을 고정한다. 형 검사·린트는 고정 장치로 치지 않는다.
- 동작을 지키는 작은 걸음으로 옮기고 걸음마다 고정 장치를 통과시킨다. 정리 중 드러난 빠진 기능·실제 버그는 떼어 따로 다룬다.
- 끝에 고정 장치를 다시 돌리고, 처음 정한 전체 대상과 결과를 대조한다.

## 화면

- 브라우저·웹뷰에 닿는 변경은 바뀐 화면을 실제로 열고 요청한 경로를 조작해 확인한다. 버튼 문구처럼 작은 수정은 그 대상과 연결된 동작만 확인한다.
- 창 크기를 정한 데스크톱 앱 화면은 그 크기에서, Windows 화면 배율 100%·150% 로 잘림·겹침·스크롤을 확인한다.
- 화면의 콘솔 오류·경고와 실패한 네트워크 요청을 보고 변경 전부터 있던 문제와 이번 변경의 새 문제를 가른다.
- 닿을 수 없는 로그인·기기·환경은 미확인으로 남긴다.

## 끝 확인

요청한 결과와 확정한 범위로 완료를 판정한다.

1. 마지막 관련 변경 뒤 요청과 사용자 결정을 실제 결과에 대조한다. 필수 연결과 회귀 위험이 남으면 이어 처리한다.
2. 소스 수정과 실행 중 앱을 구분한다. 필요한 빌드·재실행·설정 적용 뒤 사용자가 쓸 경로에서 확인한다. 화면은 동작·오류·상태를 직접 열고, 설치 산출물은 그 산출물을 실행한다.
3. 저장·권한·부분 실패·재시도·복구가 닿으면 성공 경로와 거절·실패 경로를 함께 확인한다. 같은 원인의 다른 호출자도 살핀다. 장비·공유 폴더·예약 작업에 닿는 기능은 실패 하나를 일으켜 설치본 로그에서 미리 적은 질문에 답하는 줄을 찾는다.
4. 환경이나 외부 데이터가 바뀌었으면 영향을 받는 검증만 다시 한다. 코드가 바뀌지 않았으면 통과한 검사를 되풀이하지 않는다.
5. 결과에는 바뀐 동작, 실제 실행한 확인, 남은 제약을 적고 정적 검사·모의 실행·실제 브라우저·설치판·외부 서비스 검증의 범위를 가른다.
