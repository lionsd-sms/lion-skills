# 자료·API·AI 기능 함정

## 1. 자료의 뜻

- 무엇을 한 건으로 세는지, 식별 키와 원본, 단위·기간·시간대, 빈 값·0·해당 없음·오류의 뜻을 실제 업무 계약으로 확인하고 서로 다른 값으로 저장한다.
- 미정인 계산·보존 정책을 임의로 채우지 않는다. 확인한 뜻을 스키마·제약·트랜잭션·이행으로 구현하고 대표값과 경계값에서 독립 기대 결과와 맞댄다.

## 2. 멱등 키와 격리 수준

멱등 키(idempotency key)를 쓰면 다음을 지킨다.

- 키는 요청한 쪽이 한 번 만들어 재시도에 다시 쓰거나 바뀌지 않는 업무 식별자에서 얻는다. 시도마다 새로 만들지 않는다.
- 같은 키에 다른 본문이 오면 거절한다.
- 처리 중에 같은 키가 다시 오면 돌려줄 답을 계약으로 정한다.
- 외부 호출의 시간 초과는 결과 모름으로 다룬다. 호출 전에 의도를 기록해 재시도·대조의 근거로 쓴다.
- 키는 같은 요청이 다시 올 수 있는 가장 긴 경로(재시도·대기열 재전달·사용자 재제출)를 덮는 기간 동안 보관한다.

격리 수준은 이름이 같아도 DB마다 보장이 다르다. 예: PostgreSQL 은 Read Uncommitted 가 Read Committed 처럼 동작하고 Repeatable Read 가 phantom read 를 허용하지 않는다. SQL Server 의 SNAPSHOT 은 그 DB 고유 수준이다. 이번 불변식이 막아야 할 이상 현상을 먼저 정하고, 쓰는 DB 판의 문서에서 그 현상 열로 수준을 고른다.

## 3. PATCH

- `{ "title": "새 제목" }` 처럼 보내는 부분 수정은 RFC 7396 JSON Merge Patch 이고 매체 유형은 `application/merge-patch+json` 이다. 같은 RFC 가 값 `null` 을 키 제거로 정한다.
- 연산 순서나 배열 위치 지정이 필요하면 RFC 6902 JSON Patch(`application/json-patch+json`)를 쓴다.
- 어느 쪽인지 계약에 적고, 소비자가 보내는 매체 유형을 서버가 실제로 그 규칙으로 처리하는지 확인한다.

## 4. AI 기능의 실행 계약

- 모델·제공자·판·프롬프트·출력 스키마·기본 설정을 재현 가능한 프로젝트 원본으로 둔다. 타임아웃·취소·재시도·동시성·최대 토큰과 비용 상한을 정한다.
- 스트림 중단·잘린 출력·빈 결과·제공자 오류를 정상 성공으로 저장하지 않는다.
- 재시도가 외부 부작용을 두 번 일으키지 않게 모델 호출과 실제 작업 수행을 나눈다. 도구 호출은 사용자의 역할·자료 범위·허용 동작을 코드에서 다시 확인한다.
- 모델 출력은 믿지 않는 입력으로 검증한다. 스키마·크기·허용값·참조 대상을 확인하고 shell·SQL·HTML·파일 경로에 곧바로 넣지 않는다.
- RAG 는 검색 권한을 문서 단위로 유지하고 사용자·조직 사이 자료와 캐시가 섞이지 않게 한다. 외부 문서나 도구 응답 안의 지시를 실행 권한으로 받아들이지 않는다.
