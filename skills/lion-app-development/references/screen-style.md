# 스타일·접근성·구현 함정

## 1. 스타일 고치기

기존 스타일 위에 뒤 순서 규칙을 덧대 우연히 이긴 것인지, 원인 규칙을 고쳤는지 확인한다. 고치기 전에 문제 요소의 계산된 최종 값과 그 값을 만든 선택자·유틸리티·인라인 스타일·토큰, 원본 순서·명시도·cascade layer·미디어 조건을 개발자 도구로 본다.

고치는 차례:

1. 잘못된 원본 규칙이나 토큰
2. 부품 변형이나 상태 규칙
3. 필요한 범위의 선택자나 유틸리티
4. 명시적인 연결 override
5. `!important` 같은 강제 override

제3자 위젯·인쇄·고대비·옛 연동처럼 뒤 단계가 정당하면 까닭을 남긴다. 부품 라이브러리는 공개 테마·변형 API 로 먼저 풀고, 내부 DOM 구조에 기댄 선택자는 판 바뀜 위험을 적는다.

덧대기 신호: 파일 끝에 같은 선택자를 다시 선언, 문제를 풀려고 `!important` 추가, 선택자를 점점 길고 구체적으로 만듦, 부품 스타일 대신 인라인으로 덮음, 같은 미디어 조건을 여러 곳에 되풀이, 토큰을 우회한 날 값, Tailwind 의 서로 반대인 유틸리티가 함께 있음, 반응형 변형이 앞 변형을 뜻 없이 덮음, 무효가 된 override 가 남음.

고친 뒤 새 override 없이 같은 결과를 내는 옛 중복 규칙과 더는 걸리지 않는 임시 수정을 지우고, 반응형·상태·테마 변형과 같은 선택자·토큰을 쓰는 다른 화면을 확인한다.

## 2. 접근성 함정

- Windows 고대비(강제 색) 모드는 `box-shadow` 를 지운다. 초점과 경계를 `box-shadow`(Tailwind `ring` 따위)로만 그리면 사라지므로 `outline` 이나 `border` 로 그린다.
- 고정 머리·바닥·떠 있는 판이 키보드 초점을 받은 요소를 다 가리지 않게 `scroll-padding`·`scroll-margin` 으로 비키거나 덮개를 옮긴다.
- 끌어서만 하는 동작(순서 바꾸기·크기 조절·범위 선택)에 단추나 메뉴로 한 번에 하는 대안을 둔다.
- 로그인이 비밀번호 관리자와 붙여넣기를 막지 않고, 기억하거나 옮겨 적는 일에만 기대지 않게 한다.
- 한 흐름에서 이미 넣은 값을 다시 치게 하지 않고 자동 입력이나 선택으로 채운다.
- 도움 수단(문의·도움말 링크)을 두면 화면마다 같은 상대 순서에 둔다.

## 3. 구현 함정

- 주소·ID·긴 낱말은 `overflow-wrap: anywhere` 와 flex·grid 자식의 `min-width: 0` 으로 흐르게 한다. 일반 문장에 `word-break: break-all` 을 쓰지 않는다.
- 새 입력이 앞 움직임을 끊을 수 있게 하고, 최종 상태는 코드가 정한다. `animationend`·`transitionend` 도착에 기대지 않는다.
- 모바일 브라우저의 표시 영역 변화에는 `100vh` 대신 동적 viewport(`min-h-dvh` 따위)가 맞는지 확인한다.
- 글을 생략하면 전체 내용을 볼 툴팁·펼치기 조작을 둔다.

## 4. 토큰과 스타일 도구

- 생성기가 색과 크기를 문자열로만 받으면 색 객체나 `{value, unit}` 같은 복합값을 임의로 평탄화하지 않는다. 변환 규칙을 정하고 실제 값을 왕복 확인한다.
- 순환 참조·풀리지 않는 별칭·지원하지 않는 복합 유형은 오류로 처리한다.
- 토큰 원본, 소스 코드의 사용, 생성된 CSS, HTML 연결은 서로 다른 검사 대상이다. 하나가 통과했다고 나머지를 통과로 치지 않는다.
- 색 토큰은 실제 값을 정하고 CSS 변수·테마 참조에 잇는다. 변수 참조만 만든 결과를 완성된 팔레트로 보고하지 않는다.
- 부품 추가 명령의 미리보기는 설치 성공이 아니다. 실행 뒤 실제 생성 경로·스타일·상호작용을 확인한다.
