# 문서 제작

독자의 목적에 맞게 문서를 쓰고 고치고 바꾸며, 원문의 사실·조건·숫자·인용을 지키고 최종 파일을 다시 열어 확인한다.

## 함께 여는 스킬

이 스킬을 열면 아래 조건에 맞는 스킬을 일을 시작하기 전에 바로 함께 연다.

- 기존 파일을 고치거나 다른 형식으로 바꾸거나 결과 파일을 낼 때: `lion-file-work`

## 바로 할 일

1. 작업 폴더에 요청서·DESIGN.md·구성표가 있으면 그 값 이름과 확정 문구를 그대로 쓴다.
2. 독자의 목적과 원문에서 지킬 사실·조건·숫자·인용을 확인한다. 짧은 문구 수정은 필요한 문장만 고친다.
3. 보고서·회의록·제안서는 독자가 내릴 결정을 먼저 정하고 결정 → 근거 순서로 쓴다. 설명서·README·API 같은 사용 문서는 종류를 하나 정한다: 따라 하기(배우며 행동), 방법(일하며 행동), 참고(일하며 찾아봄), 설명(배우며 이해). 사용 문서 한 편에 종류를 섞지 않는다.
   - 따라 하기는 단계마다 눈에 보이는 결과와 기대 출력·화면을 적는다.
   - 참고 문서에는 지시·설득·의견을 넣지 않고 사실·선택지·한계를 단정하게 쓴다. 의견은 설명 문서에만 둔다.
4. 원료에서 긴 글을 만들 때는 글감 모으기 → 뼈대 세우기 → 다듬기 순서로 간다. 긴 문서·양식·여러 파일은 구성과 보존 요소를 먼저 정한다.
5. 기존 파일은 복구 가능한 사본에서 고치고, 저장한 파일을 다시 열어 내용·구조·필요한 쪽의 렌더링을 확인한다.
