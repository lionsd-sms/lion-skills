# 표준화

"표준화해줘"로 고른 틀에 맞춰 옮길 때, "규칙 정리해줘"에서 틀을 고른 뒤 범위를 정할 때, 차이 목록과 README 「역할 | 위치 | 뜻」 표에 항목을 분류할 때 쓴다.

## 1. 표준화와 범위

"표준화해줘"는 고른 틀로 프로젝트 전체를 옮기는 요청이다.

1. 옮길 틀을 정한다. `틀:` 줄에 틀 이름이 있으면 그 틀이고, 없으면 처음 정하기의 틀 질문·항목 질문으로 묻는다.
2. 차이 목록을 보인다: 축 · 지금 · 바뀔 모양 · 영향(경로를 쓰는 명령·설정·문서).
3. 복구 기준점(커밋 또는 묶음 백업)을 만든 뒤 옮긴다.
4. 규칙 문서에 적힌 자리·이름 규칙 가운데 틀과 다른 것도 틀에 맞게 고친다.
5. 옮긴 뒤 빌드·시험·실행으로 전과 같이 동작하는지 확인한다.

표준화는 아래가 맞아야 끝난다.

- 사람이 누르는 실행 파일을 틀이 정한 자리와 이름으로 찾아 실행한다. 틀이 정하지 않았으면 프로젝트 관례·프레임워크 기본을 따른다.
- 역할 영역마다 책임과 권위 있는 주인이 분명하다.
- 과거·외부·생성·개별 항목(2절)은 지금 자기 원본·문서와 탐색에서 구별되고 출처가 이어진다.
- 지금 코드 규모에 맞는 책임 경계와 다음 확장 자리가 보인다.
- 기본 개발 문서와 적용 계약이 지금 사실을 반영한다.
- 같은 사실과 같은 틀로 다시 표준화하면 같은 구조가 나온다. 이미 맞춘 요소는 두고 새 사실이 생긴 부분만 다시 판단한다.

"규칙 정리해줘"처럼 옮기기를 말하지 않은 요청에서 틀을 골랐으면 규칙 문서를 만들고 범위를 묻는다. 선택지마다 이 프로젝트의 실제 예를 붙인다.

```text
지금 파일을 어디까지 새 틀에 맞출지 고르세요.
가. 앞으로 하는 일만 (추천). 지금 파일·폴더는 두고 다음 작업부터 새 틀을 씁니다. 예: <지금 커밋 꼴> → <틀의 커밋 꼴>
나. 빈 곳만. 지금 관례가 있는 축은 두고 관례가 없는 축만 새 틀로 채웁니다. 예: <관례 없는 축>
다. 전체 정리. 폴더·문서·이름까지 옮깁니다. 시작 전에 바뀔 목록과 복구 기준점을 보입니다. 예: <옮길 폴더>
```

| 범위 | 할 일 |
|---|---|
| 앞으로 하는 일만 | 이미 있는 파일·폴더는 옮기거나 이름을 바꾸지 않는다. 다음 작업부터 과정(커밋 꼴, 작업 기록)과 새로 만드는 파일의 자리·이름은 틀을 따른다 |
| 빈 곳만 | 틀은 적힌 규칙과 확인한 관례가 정하지 않은 축만 채운다 |
| 전체 정리 | 위 표준화 순서로 옮긴다 |

## 2. 항목 분류

표준화의 차이 목록과 README의 「역할 | 위치 | 뜻」 표는 항목을 이름보다 역할로 적는다. 분류만으로 새 폴더·문서를 만들지 않는다.

역할은 정문 · 제품 코드 · 검증 · 문서 · 자동화 · 설정 · 자원 · 자료 · 도구 · 빌드 결과 · 전달물이다. 다른 문서가 Entry · Active Code · Verification · Documentation · Automation · Configuration · Resources · Data · Tools · Build Artifacts · Delivery 로 쓰면 같은 순서의 역할로 읽는다. 한 항목은 지금 책임을 가장 잘 설명하는 역할 하나를 먼저 쓴다.

판단에 걸리는 축만 속성으로 붙인다.

| 축 | 값 | 가르는 것 |
|---|---|---|
| 현행성 | 현행 · 과거 | 지금 구현·계약의 일부인가, 비교·감사·복구용인가 |
| 소유 | 자기 · 외부 | 이 프로젝트가 권위를 가지나, 상위 공급자가 가지나 |
| 원천 | 원본 · 생성 | 직접 유지하나, 다른 원본·명령에서 만들어지나 |
| 범위 | 공유 · 개별 | 저장소·팀의 기준인가, 사용자·장비·세션별 상태인가 |

- 예: 외부 SDK 사본은 「제품 코드 또는 자원 · 현행 · 외부 · 원본 · 공유」, 개별 빌드 캐시는 「빌드 결과 · 현행 · 자기 · 생성 · 개별」.
- 과거 항목은 비교·감사·복구 근거로 쓴다. 생성 항목은 생성 원본·명령과 잇는다. 개별 항목의 사실은 공유 기준으로 넓히지 않는다.
- 문서의 작성·진행 상태(Active · Planned · Archived)는 이 속성과 따로 적는다.
