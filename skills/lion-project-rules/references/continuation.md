# 이어가기

중단·재개·인계에 쓴다. 상태는 프로젝트 규칙 문서의 「진행 상태와 다음 할 일」에 둔다. 프로젝트에 작업 기록 문서(TASK 문서, 작업일지)가 있으면 그 문서에 쓰고 이 절에는 경로만 둔다.

## 1. 다시 시작할 때

1. 범위를 정하고 말한다: 어느 일(주제), 어느 기간(기본은 최근 7일), 어느 프로젝트(기본은 지금 폴더). 다른 프로젝트의 기록은 사용자가 말할 때만 읽는다.
2. 「진행 상태와 다음 할 일」·「정해진 결정」·작업 기록을 먼저 읽는다. "기록에 없다"고 말하기 전에 규칙 문서가 가리키는 기록 자리(결정 문서, TASK 문서, 프로젝트 기억 폴더)를 모두 본다. 결정은 사용자 원래 말이 붙은 범위로만 따르고, `해석`이나 `미정` 표시가 있으면 그 범위를 넓히지 않는다. 같은 요약이 여러 문서에 복사되어 있으면 근거 하나로 센다.
3. 지금 상태와 맞대 본다: 작업 트리(`git status`), 커밋하지 않은 변경, 최근 커밋, 브랜치·PR, 실행 중인 프로세스, DB·배포·외부 전송의 실제 반영.
4. 적힌 계획과 지금 상태가 다르면 지금 상태를 따르고 다른 점을 알린다. 이전 기록은 이어받는 근거다. 끝낸 단위와 받은 결정은 다시 하지 않고, 재현·조사를 처음부터 되풀이하지 않는다. 새 사실로 깨진 전제만 다시 연다.
5. 확인을 다시 돌리는 때: 기록에 확인 명령·결과가 없을 때, 그 뒤 코드가 바뀌었을 때, 다음 단위가 그 확인에 기댈 때.
6. 승인은 기록에 적힌 것만 이어받는다. 지난 대화에서 들은 듯한 승인으로 커밋·배포·삭제를 하지 않는다.
7. 결과를 잃은 전송·배포·자료 변경은 반영되었는지부터 확인하고 한 번만 다시 한다.
8. 재개 지점을 이름 붙여 보이고 이어서 한다. 끝 보고 전에는 이어받은 「확인함」을 원래 목표에 비춰 실물로 확인한다.

규칙 문서가 없으면 git 상태·최근 커밋·바뀐 파일로 답한다. 상태를 남길 자리를 만들지는 사용자에게 묻는다.

### "어디까지 했지"에 답하는 꼴

```text
요약 (다섯 줄 이내): 무슨 일이고 전체가 어디까지 왔나
흐름 (한 줄씩, 상태 꼬리표 하나):
  [커밋됨 <해시>] · [PR 열림 #N] · [진행 중 <브랜치>] · [확인함·미커밋] · [되돌림 <해시>] · [계획만]
되풀이된 문제 (다섯 이내): 되돌린 수정, 계속 나오는 증상
다음 행동: 하나
```

꼬리표 없는 흐름은 끝나지 않은 것으로 보고 꼬리표를 붙인다. 화면을 넘으면 흐름을 지우기 전에 세부를 줄인다. 걸리지 않는 이웃 일은 넣지 않는다. 승인된 일이 있으면 답한 뒤 이어서 한다.

## 2. 멈추거나 넘길 때

사용자가 멈추라고 할 때만 멈춘다. "계속해", "자는 동안 해줘"는 이어서 하라는 말이다.

1. 안전한 경계에서 멈춘다: 지금 단계를 끝내거나 되돌린다. 새 일을 시작하지 않고 돌던 서브 에이전트를 멈춘다.
2. 멈추려고 되돌리기 어려운 일(push, PR, 배포)을 하지 않는다.
3. 변경을 잃지 않게 한다. 프로젝트 규칙이나 사용자가 커밋을 허락했으면 `wip:` 커밋 하나로 남기고, 아니면 커밋하지 않은 채 두고 그 사실을 적는다. 빌드가 깨진 상태면 그렇다고 적는다.
4. 남길 것(필요한 것만):
   - 목표와 범위, 확정한 답과 받은 승인
   - 바뀐 파일, 그때의 커밋 해시와 미커밋 변경 여부, 실행 중인 것, 복구 기준점
   - 돌린 확인 명령과 결과를 그대로
   - 재개 뒤 쓸 자료(문구, 개수, 순서)는 줄이지 않고 그대로. 남긴 파일을 다시 열어 그대로인지 확인한다
   - 남은 일, 막힌 까닭과 누가 풀어야 하는지, 열린 질문
   - 주의할 것(빠지기 쉬운 함정)
   - 다시 시작할 때 첫 행동 하나

남긴 글의 주장(끝남, 통과, 원인)마다 근거가 된 명령·파일을 붙인다. 근거가 없는 주장은 `추정`이라 표시한다.

멈출 때 이번 작업이 띄운 시험 실행은 정리하고, 사용자가 띄운 실행은 그대로 둔다.

## 3. 다른 세션·에이전트에 넘길 때

- 받는 쪽은 이 대화를 모른다고 보고 쓴다. 규칙 문서·작업 기록·계획·커밋·바뀐 파일에 이미 있는 내용은 옮겨 쓰지 않고 경로로 가리킨다.
- 새 세션으로 넘기는 때는 작업 단위가 끝난 경계다. 넘기기 전에 이번 대화에서 정한 결정을 규칙 문서·계획 파일에 먼저 적는다.

## 4. 자리 비움과 예약

- 사용자가 자리를 비워도 승인된 독립 작업은 계속한다. 새 삭제·설치·배포·외부 전송·비용 권한은 생기지 않는다.
- 감시·알림·반복 실행은 사용자가 요청하고 지금 도구가 지원할 때만 만든다. 만들기 전에 한 번 직접 끝까지 돌려 보고, 회차마다 통과·실패가 기록에 남게 한다. 같은 목적의 예약이 있으면 새로 만들지 않고, 이번에 만든 예약은 목표가 끝나면 지운다.
