# 현장 Windows 도구 틀: 실행 파일·판·기록

이 틀을 써 온 사용자의 프로젝트에서 「폴더 틀」 절이 `틀: 현장 Windows 도구 틀`일 때 쓴다. 실행 파일, 판 번호와 보관, 작업 기록(TASK), 커밋, 규칙 문서에 옮겨 적을 화면·문구 원칙의 자리와 꼴을 정할 때 연다. 이번 일에 걸리는 절만 읽는다.

## 1. 실행 파일

| 역할 | 이름과 자리 |
|---|---|
| 개발 실행 | 루트 `<앱>-개발 실행.bat`. 프로젝트 개발 명령(예: `app/`에서 `npm run tauri dev`)을 부른다 |
| 빌드 배포 | `<앱>-빌드\<앱>-빌드 배포.bat`. 결과는 같은 폴더의 결과 하위 폴더에 두고 빌드마다 그 하위 폴더만 비우고 다시 채운다 |
| 판 보관 | `<앱>-버전\<앱>-버전 보관.bat` |
| 검사 | 실행 파일을 두지 않는다. AI가 프로젝트 명령(예: `npm run check`)으로 돌린다 |
| 빌드·배포 문서 | `docs/09-delivery/delivery.md` |

- 실행 파일은 그 결과가 쌓이는 폴더 안에 둔다. README 빠른 시작에 이름을 적는다.
- 이 표는 이름과 자리만 정한다. 실행 파일은 요청이나 정해진 결정이 그 역할을 요구할 때 만든다.
- .bat 안쪽 글자는 영문·숫자만 쓴다. 한글 출력은 부르는 PowerShell 스크립트에 둔다.

## 2. 판 번호와 보관

- 판 번호의 기준은 루트 `VERSION` 한 줄(예: `1.2.0`)이다. 패키지·앱 설정의 번호(`app/package.json`, `app/src-tauri/Cargo.toml`, `app/src-tauri/tauri.conf.json` 따위)는 이것을 따르고, 검사 명령이 같은지 대조해 다르면 실패한다.
- 판을 올릴 때는 `VERSION`을 먼저 고치고 나머지를 맞춘 뒤 CHANGELOG의 다음 판 절을 그 판의 절로 바꾼다.
- `<앱>-버전\v<판>\`에는 사용자가 "이 판으로 나간다"고 정해 보관 실행 파일을 직접 누른 판만 들어간다. 검사 통과로 저절로 넣는 장치를 만들지 않는다.
- 판 폴더 내용: 설치 파일·포터블, `출처.md`(코드 커밋, 커밋하지 않은 변경 여부, 만든 시각, 검사 명령과 결과, 산출물 식별), `README.md`(그 판의 목표와 바뀐 점). `<앱>-버전\README.md`에는 넣는 조건·구조·덮어쓰지 않는 규칙을 적는다.
- 같은 판 폴더가 있으면 덮어쓰지 않고 판을 올릴지 묻는다. 설치 파일·포터블은 Git에 넣지 않는다.

## 3. 작업 기록(TASK)

- 이 틀의 앱은 파일을 바꾸는 작업이면 버튼 글자 하나를 고쳐도 고치기 전에 TASK 문서를 쓰고, 끝나면 TASK-HISTORY에 한 줄을 더한다. 점검만 하는 요청은 쓰지 않는다.
- 자리와 번호: `docs/12-records/tasks/TASK-YYYY-MM-DD-N.md`, N은 그날의 순번(1부터).
- 고치기 전에 목표 · 결정 · 지금 상태 · 바꿀 범위 · 완료 조건과 확인 방법 가운데 이어가기에 필요한 것을 적는다. 나눠 맡기면 같은 문서에 입력과 쓰기 경계를 적는다.
- 끝나면 결과(한 일, 확인한 증거, 확인 못 한 것)와 커밋 번호를 채우고 `docs/12-records/TASK-HISTORY.md`에 `TASK · 목적 · 결과 요약 · 주요 커밋` 한 줄을 더한다.
- TASK 문서가 목표·결정·상태·확인·다음 할 일을 담으므로 다른 원장을 따로 만들지 않는다. 규칙 문서의 「진행 상태와 다음 할 일」에는 진행 중인 TASK 경로만 둔다.
- 앱 규칙을 바꾸면 바꾼 까닭을 그 일의 TASK 문서에 남긴다.

## 4. 커밋

```text
<약속어>: <TASK 번호> <한국어 현재형 한 줄>
fix: TASK-2026-10-19-1 목록이 비면 새 항목 단추를 보인다
```

- 약속어: `feat`(기능) · `fix`(고침) · `docs`(문서) · `refactor`(정리) · `chore`(잡일).
- 둘째 줄부터 본문과 확인한 증거(돌린 명령과 결과, 직접 본 화면)를 적는다.
- 커밋 뒤 TASK 문서와 TASK-HISTORY에 커밋 번호를 잇는다. 기록을 채우려고 승인받지 않은 커밋을 하지 않는다.

## 5. 규칙 문서에 옮겨 적을 화면·문구 원칙

새 프로젝트를 이 틀로 만들 때 「화면·문구 원칙」 절에 아래 줄을 적는다. 화면을 만드는 세부 기준은 이 틀에 두지 않는다.

- 화면은 값과 동작만 보인다. 까닭·안내·다음 확인은 실행 로그에 둔다.
- 오류 `실패 대상 · 실패`, 상태 `라벨 · 값`, 빈 상태 `종류 · 없음`. README·개발 문서는 평서형, CHANGELOG는 존댓말.

색·밝기·글꼴, 화면에 영어 낱말을 둘지, 앱이 PC에 두는 설정·캐시 자리 같은 앱 하나의 제품 규칙은 이 틀이 정하지 않고 앱마다 정한다.
