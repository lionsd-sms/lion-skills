# 판·빌드·배포

판 번호를 올리고 빌드·설치판을 만들고, 서명 요구를 다루고, 출시 준비를 판정하고 배포할 때 쓴다.

## 1. 판 번호와 판 보관

판 번호는 한 곳을 기준으로 정하고 패키지·빌드·앱 설정의 번호가 그것을 따른다. 규칙 문서의 「폴더 틀」 절(`틀:` 줄)이 판 번호 파일(예: 루트 `VERSION`)과 판 보관 자리를 정했으면 그 틀을 따른다. 판을 올릴 때는 기준 번호를 먼저 바꾸고 나머지 번호와 변경 기록의 해당 절을 맞춘 뒤 검사 명령으로 불일치를 실패 처리한다. 빌드 결과 폴더는 빌드마다 비워 이전 설치판이 섞이지 않게 하고, 실행 파일과 README 는 보존한다.

판 보관은 사용자가 그 판을 출시할 판으로 정해 보관을 직접 시킨 때만 한다. 검사나 실기 확인 통과만으로 보관하지 않는다. 같은 판 폴더가 있으면 덮어쓰지 않고 판을 올릴지 묻는다. 보관한 판에는 코드 커밋·미커밋 변경·만든 시각·검사 명령과 결과·산출물 식별을 적은 출처 기록과 확정한 설치 파일을 두고, 설치 파일은 Git에 넣지 않는다.

빌드를 보고할 때는 기준 커밋, 결과 파일과 크기, 하지 않은 것(설치·실행)을 적는다.

## 2. Tauri 2 Windows 설치판

프로젝트가 고른 설치 방식·실행 권한·WebView2 배포 방식·게시자·서명 정책을 실제 번들 설정과 만들어진 설치판에서 대조한다. 설치·업데이트·제거와 사용자 자료 보존에 닿는 변경은 지원하는 Windows 환경에서 실제 경로를 확인하고, 확인하지 못한 조합은 갈라 보고한다. 기존 설치 정책의 이름이나 기본값은 사용자 결정 없이 바꾸지 않는다.

## 3. 서명

코드 서명은 고객·계약이 요구할 때만 다룬다. 플랫폼이 서명을 요구해도 들일지는 고객·계약이 정한다. 요구가 없으면 새 서명 체계를 만들지 않고, 서명을 배포 조건이나 보고 항목으로 두지 않는다. 프로젝트가 이미 쓰는 서명·공증 방식은 지우거나 바꾸지 않는다. 요구가 있으면 검증한 산출물과 실제로 서명·게시한 산출물이 같은 식별값인지 확인한다.

## 4. 출시·배포 준비 상태

| 상태 | 뜻 |
|---|---|
| 준비됨 | 필수 근거가 통과했고 알려진 위험이 허용 범위다 |
| 알려진 위험과 함께 준비됨 | 결정적 차단 밖의 위험이 있고 수락 근거가 필요하다 |
| 준비 안 됨 | 필수 검사가 실패했거나 뜻 있는 검증 차단이 있다 |

보안·자료 무결성의 결정적 차단은 준비 안 됨이다. 결과를 가르는 확인 못 함이 출시·배포 결정을 바꾸면 차단이나 알려진 위험으로 밝힌다.

## 5. 배포 차례

1. 출시 산출물·대상 환경·배포 명령이나 흐름을 다시 확인한다.
2. 대상이 불명확하거나 환경을 헷갈릴 수 있으면 사용자에게 묻는다.
3. 준비됨이면 기존 배포 경로로 진행한다.
4. 알려진 위험과 함께 준비됨이면 사용자 수락이나 기존 정책의 사전 허용 근거를 확인한다.
5. 준비 안 됨이면 차단을 풀거나 보고한 뒤 다음 결정을 받는다.
6. 실제 배포 경로를 실행하고 산출물·판이 반영됐는지 확인한다.

설치형 앱의 업데이트를 올리는 일은 모든 현장 PC 에 새 판이 깔리는 일이다. 한 대에 먼저 깔아 핵심 흐름을 확인한 뒤 나머지에 올린다.

DB·설정 파일 형식을 바꾸는 판은 직전 판 설치판을 남기고, 새 판이 처음 돌 때 바꾸기 전 자료 사본을 남긴다. 직전 판을 새 자료 위에 깔아 열어 본 뒤에 「되돌릴 길 확인함」으로 적는다.

실패하면 기존 복구 정책을 먼저 따른다. 정책이 불명확한 파괴적 복구는 사용자 결정으로 올린다.

배포 직후 이 순서로 확인한다: 상태 확인 응답 → 새 오류 종류 → 지연 → 핵심 흐름 한 번 직접 실행 → 로그가 흐르고 읽히는지 → 되돌리기 장치가 준비 상태인지.

## 6. 완료 상태

| 상태 | 뜻 |
|---|---|
| 출시함 | 정한 출시 산출물·판을 만들었고, 게시가 범위면 그 채널에 반영된 것까지 확인했다 |
| 배포함 | 대상 환경에 정한 산출물·판이 반영된 것을 확인했다 |
| 확인 못 함 | 필요한 게시·실행·실행 뒤 근거가 남아 상태를 다 검증하지 못했다 |

실행 상태와 검증 상태를 갈라 적는다. 예: `배포함 / 확인 못 함`. 지금 확인할 수 없는 운영 결과는 다음 관찰의 시점·조건·담당을 프로젝트 규칙 문서의 「진행 상태와 다음 할 일」 절이나 이미 쓰는 이슈·배포 기록에 적는다.
