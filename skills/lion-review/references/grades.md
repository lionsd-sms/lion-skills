# 지적 등급과 형식

## 1. 등급

등급은 영향으로 정한다.

| 등급 | 기준 |
|---|---|
| 높음 | 요청·완료 기준을 못 채움, 확정 결정과 어긋남, 데이터 손실, 보안 구멍, 기존 기능이 깨짐, 시험이 거짓으로 통과 |
| 중간 | 돌지만 요구한 꼴·경계 사례·오류 처리 하나가 빠짐, 프로젝트 규칙과 어긋남, 요청 밖 추가나 쓰이지 않는 추상화가 고칠 곳을 늘림 |
| 낮음 | 이름·문구·정리·읽기 편함 |

- 덜 짓기 지적은 영향에 따라 중간이나 낮음으로 단다. 요청 밖 추가가 기존 동작을 바꾸면 높음이다.
- 결과물이 문서·표·발표면 같은 기준을 그 결과물에 맞춰 읽는다. 예: 수치가 원자료와 다름은 높음, 요청한 절이 빠짐은 높음, 표 서식이 규칙과 다름은 중간, 맞춤법은 낮음.

## 2. 지적으로 내는 조건

- 위치와 근거 인용이 있다. 근거는 요청 원문, 확정 결정, 규칙 파일:줄, 시험 출력, 원자료 가운데 하나다.
- 영향을 한 줄로 말할 수 있다.
- 이번 변경 안에 있다. 이번 변경 밖에서 본 문제는 등급 없이 「범위 밖 발견」 줄에 적는다.
- 근거를 대지 못한 의심은 등급 없이 「의심」 줄에 적고 고칠 목록에 넣지 않는다.
- 해롭지 않은 중복, 변경 안에서 이미 처리된 것, 입력이 막혀 일어나지 않는 경계 사례, 일관성만 맞추는 손질, 시험 고정값, 검사 도구가 이미 잡는 것은 지적하지 않는다.
- "이 값이 비어 오면?" 꼴의 지적은 호출처를 따라가 실제로 그 값이 오는 길을 보일 때만 낸다.
- 추상화·함수 뽑기를 권하는 지적은 그 코드가 두 번째 방식으로 바뀔 쓰임이 있을 때만 낸다.
- "나라면 다르게 했다"는 지금 방식의 구체적 문제를 보이지 못하면 지적으로 내지 않는다.
- 요청·확정 결정이 옳은지는 따지지 않는다. 요청끼리 부딪치거나 요청대로 하면 데이터 손실·보안 구멍이 생기면 등급 없이 「범위 밖 발견」에 적는다.
- 찾은 것이 낮음뿐이면 대상은 쓸 만하다는 뜻이다. 판정 뒤에 「낮음뿐」을 붙이고, 낮음은 고칠 값이 있는 것만 적는다.
- 영향은 잴 수 있으면 잰 값으로 쓴다. 실제 문제를 "작은 걱정" 처럼 낮춰 쓰지 않는다.

## 3. 검수 답

```
판정: 지적 없음 | 지적 있음(높음 a · 중간 b · 낮음 c) | 막힘(까닭)
대상 판본: <커밋 · 미커밋 변경 · 파일 목록>
본 범위: <연 파일 · 돌린 시험 · 시도한 반례와 결과>
못 본 범위: <열지 못한 곳 · 돌리지 못한 시험>

[1] 높음 · 요구 대조 · src/save.ts:42
    무엇: 저장 실패 때 입력이 지워진다
    근거: 요청 "저장 실패해도 입력은 남긴다" / 42줄 form.reset() 이 catch 앞에 있음
    방향: 성공한 뒤에만 비운다
[2] 낮음 · 기준 · docs/guide.md:10
    ...

범위 밖 발견: <있으면>
의심: <근거를 대지 못한 것, 있으면>
```

- 축은 요구 대조 · 기준 · 덜 짓기 가운데 하나를 단다.
- 높음부터 적는다. 구조 지적 하나와 낮음 열 개가 나오면 구조 지적이 검수의 본론이다.
- 방향에는 옮길 꼴을 쓴다. 예: 조건 사슬 → 자료형 모델, 넘기기만 하는 층 → 지우고 바로 부르기.
- 막힘은 자료·권한·도구가 없어 검수를 끝내지 못했다는 뜻이다. 지적이 많으면 `지적 있음` 으로 쓴다.
- 지적이 없으면 `판정: 지적 없음` 과 본 범위·못 본 범위만 쓴다.

## 4. 고침 답

만든 쪽이 지적을 모두 받은 뒤 한 번에 고치고 번호마다 답한다.

```
[1] 고침 — src/save.ts:40-45, 저장 실패 시험 추가
[2] 고침 안 함 — 낮음, 기존 문서 전체가 같은 표기라 이번에 맞추면 범위가 넓어짐
[3] 받지 않음 — 근거: 확정 결정 "중복 저장 허용"(AGENTS.md:31)
```

- 고치기 전에 지적의 인용 위치를 열어 맞는지 본다. 위치가 틀리거나 영향을 부풀렸으면 그 근거를 대고 받지 않는다.
- 높음·중간을 고치지 않으려면 근거를 댄다. 그 지적은 다시 보기에서 판정하고 남으면 올림으로 간다.
- "나중에 고친다"는 높음·중간을 고치지 않는 근거로 치지 않는다.
- 검수자가 받은 요청·결정 자료가 모자라 생긴 지적이면 빠진 자료(파일:줄, 결정 원문)를 붙여 받지 않는다. 다시 보기는 그 자료를 함께 보고 판정한다.

## 5. 다시 보기 답

같은 검수자가 고친 지적과 그 고친 자리만 본다.

```
다시 보기: 해소 n · 부분 n · 미해소 n · 새 높음 n
[1] 해소 — src/save.ts:44 성공 뒤에만 비움, 저장 실패 시험 통과 확인
[3] 미해소 — 만든 쪽 근거 AGENTS.md:31 확인, 검수 쪽 근거: 요청 원문 "같은 기록이 두 번 생기면 안 됨"
새 높음:
[N1] 높음 · 요구 대조 · src/save.ts:47 — 고친 자리에서 생김, 근거 ...
```

- 고친 자리에서 새로 생긴 중간·낮음은 끝 보고의 남은 것에 적는다.
- 부분·미해소·새 높음이 있으면 올림 한 장을 쓴다.
